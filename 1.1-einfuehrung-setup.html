Was ist Angular?

Angular ist ein vollständiges, meinungsstarkes Frontend-Framework, das von Google entwickelt und gepflegt wird. Im Unterschied zu React (eine UI-Library) oder Vue (ein progressives Framework) liefert Angular alles mitgeliefert: Router, HTTP-Client, Formular-Handling, Dependency Injection, Testing-Utilities — alles aufeinander abgestimmt und als ein einheitliches System konzipiert.

Framework vs. Library — der entscheidende Unterschied

  • Library (React): Du rufst Code der Library auf. Du entscheidest, wie du Routing, HTTP, State-Management löst. Große Freiheit, aber viele Entscheidungen.
  • Framework (Angular): Das Framework ruft deinen Code auf („Inversion of Control“). Alles hat seinen festen Platz. Weniger Freiheit, aber klare Konventionen und geringere Entscheidungsmüdigkeit im Team.

TypeScript-First

Angular wurde von Grund auf für TypeScript entwickelt — nicht nachträglich angepasst wie React. Das bedeutet: vollständige Typisierung des Cores, typisierte Template-Prüfung, generierte Typen für Services. In großen Teams zahlt sich das durch frühzeitige Fehlererkennung aus.

ℹ
Angular-Versionsgeschichte

Angular 1.x („AngularJS“, 2010) und Angular 2+ sind komplett verschiedene Frameworks. Ab Angular 2 (2016) wurde alles neu geschrieben. Wenn jemand „Angular“ sagt, meint er heute immer Angular 2+. Dieser Kurs verwendet Angular 17+ mit der modernen Standalone-API und der neuen Control-Flow-Syntax.

Wann Angular wählen?

  • Große Teams, bei denen Konventionen wichtiger sind als Flexibilität
  • Enterprise-Projekte mit langen Lebenszyklen und striktem TypeScript-Einsatz
  • Wenn vollständige Framework-Unterstützung ohne Bibliothekswahl-Overhead erwünscht ist
  • Backend-Entwickler, die ein strukturiertes Frontend bevorzugen (Angular ähnelt Spring/NestJS)

Angular Architektur — die Kernbausteine

Komponenten

Die UI besteht aus einem Baum von Komponenten. Jede Komponente hat ein TypeScript-Klasse (Logik), ein HTML-Template (Darstellung) und optional CSS-Styles. Der @Component-Decorator verbindet diese drei Teile.

Services & Dependency Injection

Geschäftslogik, HTTP-Aufrufe und gemeinsamer State gehören in Services. Angular's eingebautes Dependency-Injection-System stellt Services automatisch dort bereit, wo sie benötigt werden — ohne manuelles Instanziieren (new FlightService() ist falsch, inject(FlightService) ist richtig).

NgModule (alt) vs. Standalone (neu)

Bis Angular 14 musste jede Komponente in einem NgModule registriert werden — ein zusätzlicher Boilerplate-Container. Seit Angular 14 gibt es Standalone-Komponenten, die direkt mit standalone: true markiert werden und ihre Abhängigkeiten selbst im imports-Array angeben. Dieser Kurs verwendet ausschließlich die Standalone-API.

Change Detection

Angular's Change-Detection-Mechanismus prüft nach jeder asynchronen Operation (User-Events, HTTP, Timers), ob sich Daten geändert haben, und aktualisiert das DOM. Standardmäßig prüft Angular alle Komponenten (Default Strategy). Mit ChangeDetectionStrategy.OnPush wird eine Komponente nur beim Eingang neuer Input-Referenzen geprüft — deutlich effizienter bei großen Anwendungen.

✓
Standalone vs. NgModule: Was soll ich lernen?

In neuen Projekten verwende immer Standalone. NgModule wirst du in Legacy-Code und älteren Tutorials begegnen. Es lohnt sich, das Konzept zu verstehen, aber nicht, es aktiv zu verwenden. Die Angular CLI erzeugt seit Angular 17 standardmäßig Standalone-Projekte.

Setup — Das FlugBoard-Projekt anlegen

Angular CLI installieren

Terminal bash 
# Angular CLI global installieren (einmalig)
npm install -g @angular/cli

# Version prüfen
ng version
# Angular CLI: 17.x.x  Node: 20.x.x

Projekt anlegen

Terminal bash 
# Neues Projekt – Standalone, Routing, CSS
ng new flugboard --standalone --routing --style css

# Prompts:
# ? Which stylesheet format would you like to use? CSS
# ? Do you want to enable Server-Side Rendering (SSR)? No

cd flugboard
ng serve
# → http://localhost:4200

Standalone-Komponenten — der @Component-Decorator

Jede Angular-Komponente wird mit dem @Component-Decorator dekoriert. Bei Standalone-Komponenten setzt du standalone: true und listest alle benötigten Imports (andere Komponenten, Direktiven, Pipes) direkt im imports-Array auf.

src/app/app.component.ts typescript 
import { Component } from '@angular/core';
import { FLIGHTS }   from './data/flights';
import { Flight }    from './models/flight';

@Component({
  selector: 'app-root',       // HTML-Tag: <app-root>
  standalone: true,
  imports: [],                // Hier kommen benötigte Imports rein
  template: `
    <header>
      <h1>✈ FlugBoard Wien</h1>
    </header>

    <main>
      <table>
        <thead>
          <tr>
            <th>Flugnummer</th>
            <th>Airline</th>
            <th>Typ</th>
            <th>Zeit</th>
            <th>Status</th>
            <th>Flughafen</th>
          </tr>
        </thead>
        <tbody>
          @for (flight of flights; track flight.id) {
            <tr>
              <td>{{ flight.flightNumber }}</td>
              <td>{{ flight.airline }}</td>
              <td>{{ flight.type }}</td>
              <td>{{ flight.scheduledTime }}</td>
              <td>{{ flight.status }}</td>
              <td>{{ flight.airport }}</td>
            </tr>
          }
        </tbody>
      </table>
    </main>
  `,
})
export class AppComponent {
  flights: Flight[] = FLIGHTS;
}

Das Datenmodell

src/app/models/flight.ts typescript 
export type FlightType =
  | 'arrival'
  | 'departure';

export type FlightStatus =
  | 'on-time'
  | 'delayed'
  | 'boarding'
  | 'departed'
  | 'landed'
  | 'cancelled';

export interface Flight {
  id:            number;
  flightNumber:  string;
  airline:       string;
  type:          FlightType;
  scheduledTime: string;       // "HH:MM"
  expectedTime?: string;       // nur wenn verspätet
  status:        FlightStatus;
  airport:       string;       // Herkunft (arrival) / Ziel (departure)
  terminal:      string;       // "T1", "T2", "T3"
  gate?:         string;       // z.B. "B12"
}

Angular 17+: Neue Control-Flow-Syntax

Angular 17 hat eine völlig neue Template-Syntax für Kontrollstrukturen eingeführt: @for, @if, @else, @switch. Sie ersetzt die bisherigen strukturellen Direktiven *ngFor und *ngIf und ist direkt in den Angular-Compiler integriert — kein Import von CommonModule oder NgIf mehr nötig. Lektion 1.4 erklärt sie im Detail.

Projektschritt

Projektschritt 1.1

Statische Flugliste aufbauen

Lege das Angular-Projekt an und implementiere die statische Flugliste:

  1. Angular CLI installieren und Projekt flugboard anlegen (Standalone, Routing, CSS)
  2. Ordner src/app/models/ anlegen und flight.ts mit dem Datenmodell erstellen
  3. Ordner src/app/data/ anlegen und flights.ts mit 4 Seed-Flügen erstellen
  4. AppComponent so anpassen, dass die 4 Flüge als HTML-Tabelle mit @for ausgegeben werden
  5. ng serve starten und im Browser prüfen, ob alle 4 Zeilen erscheinen

Ziel: Im Browser ist eine Tabelle mit 4 Flügen sichtbar. Noch kein Styling nötig.

Häufige Fehler

ng: command not found

Die Angular CLI wurde nicht global installiert oder der npm-Bin-Pfad ist nicht im PATH.

Fix: npm install -g @angular/cli erneut ausführen. Danach im Terminal prüfen: echo $PATH sollte ~/.npm-global/bin oder den npm-Bin-Ordner enthalten. Alternativ: npx ng new flugboard verwenden.

Port 4200 bereits belegt

ng serve schreibt Address already in use und startet nicht.

Fix: ng serve --port 4201 oder den laufenden Prozess beenden: lsof -ti:4200 | xargs kill (macOS/Linux) bzw. im Task-Manager (Windows).

Cannot find name 'Flight'

Der TypeScript-Compiler findet das Interface nicht, weil der Import fehlt oder der Pfad falsch ist.

Fix: In app.component.ts den Import hinzufügen: import { Flight } from './models/flight';. Pfad prüfen: der Dateiname muss exakt flight.ts heißen (ohne .ts im Import).

Aufgaben

Aufgabe 1 Seed-Daten erweitern

Füge zwei weitere Flüge zu flights.ts hinzu: einen mit Status cancelled und einen mit Status departed. Stelle sicher, dass alle Pflichtfelder des Flight-Interface ausgefüllt sind und TypeScript keinen Fehler meldet.

Aufgabe 2 Tabellenspalte Terminal und Gate

Ergänze die HTML-Tabelle um die Spalten Terminal und Gate. Da gate optional ist, soll in der Zelle „—“ erscheinen, wenn kein Gate vorhanden ist. Verwende dazu den Nullish-Coalescing-Operator in der Interpolation: {{ flight.gate ?? '—' }}.

Aufgabe 3 Framework-Vergleich reflektieren

Du hast bereits React (oder ein anderes Framework) kennengelernt. Notiere drei konkrete Unterschiede zwischen Angular und deinem bisherigen Framework, die dir beim Lesen dieser Lektion aufgefallen sind. Gibt es etwas, das dir bei Angular intuitiver vorkommt? Was wirkt komplexer?

Bonus Angular DevTools erkunden

Installiere die Angular DevTools als Browser-Extension (Chrome). Starte ng serve und öffne die DevTools. Erkunde den Komponentenbaum: Welche Komponenten siehst du? Kannst du die Eigenschaft flights in der AppComponent sehen und live ändern?
