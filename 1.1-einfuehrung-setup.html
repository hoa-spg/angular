Was ist Angular?

Angular ist ein vollständiges, meinungsstarkes Frontend-Framework, das von Google entwickelt und gepflegt wird. Im Unterschied zu React (eine UI-Library) oder Vue (ein progressives Framework) liefert Angular alles mitgeliefert: Router, HTTP-Client, Formular-Handling, Dependency Injection, Testing-Utilities — alles aufeinander abgestimmt und als ein einheitliches System konzipiert.

Framework vs. Library — der entscheidende Unterschied

  • Library (React): Du rufst Code der Library auf. Du entscheidest, wie du Routing, HTTP, State-Management löst. Große Freiheit, aber viele Entscheidungen.
  • Framework (Angular): Das Framework ruft deinen Code auf („Inversion of Control“). Alles hat seinen festen Platz. Weniger Freiheit, aber klare Konventionen und geringere Entscheidungsmüdigkeit im Team.

TypeScript-First

Angular wurde von Grund auf für TypeScript entwickelt — nicht nachträglich angepasst wie React. Das bedeutet: vollständige Typisierung des Cores, typisierte Template-Prüfung, generierte Typen für Services. In großen Teams zahlt sich das durch frühzeitige Fehlererkennung aus.

ℹ
Angular-Versionsgeschichte

Angular 1.x („AngularJS“, 2010) und Angular 2+ sind komplett verschiedene Frameworks. Ab Angular 2 (2016) wurde alles neu geschrieben. Wenn jemand „Angular“ sagt, meint er heute immer Angular 2+. Dieser Kurs verwendet Angular 22 mit Standalone-Komponenten, Signals und der Control-Flow-Syntax (@for, @if).

Wann Angular wählen?

  • Große Teams, bei denen Konventionen wichtiger sind als Flexibilität
  • Enterprise-Projekte mit langen Lebenszyklen und striktem TypeScript-Einsatz
  • Wenn vollständige Framework-Unterstützung ohne Bibliothekswahl-Overhead erwünscht ist
  • Backend-Entwickler, die ein strukturiertes Frontend bevorzugen (Angular ähnelt Spring/NestJS)

Angular Architektur — die Kernbausteine

Komponenten

Die Oberfläche besteht aus einem Baum von Komponenten. Jede Komponente hat eine TypeScript-Klasse (Daten und Logik), ein HTML-Template (Darstellung) und optional CSS. Der @Component-Decorator verbindet diese Teile.

Services & Dependency Injection

Geschäftslogik, HTTP-Aufrufe und gemeinsamer State gehören in Services. Angulars Dependency Injection stellt sie dort bereit, wo sie gebraucht werden — ohne new. Das behandeln wir in Lektion 2.2.

Standalone-Komponenten

Früher musste jede Komponente in einem NgModule registriert werden. Heute ist jede Komponente standalone: Sie gibt selbst im imports-Array an, welche anderen Komponenten, Direktiven und Pipes sie verwendet. NgModule begegnen dir nur noch in älterem Code.

Signals und Change Detection

Wenn sich Daten ändern, muss Angular die Anzeige aktualisieren (Change Detection). Moderne Angular-Apps verwenden dafür Signals: Werte, die Angular Bescheid geben, sobald sie sich ändern. Damit weiß Angular genau, welche Stellen neu zu zeichnen sind. Signals führen wir in Lektion 1.2 ein, sobald sich im FlugBoard zum ersten Mal etwas ändert.

Setup — Das FlugBoard-Projekt anlegen

Angular CLI installieren

Terminal bash 
# Angular CLI global installieren (einmalig)
npm install -g @angular/cli

# Version prüfen – dieser Kurs verwendet Angular 22
ng version

Projekt anlegen

Terminal bash 
# Neues Projekt ohne Router, Server-Side Rendering und Tests
ng new flugboard --routing=false --ssr=false --style=css --skip-tests

cd flugboard
ng serve
# → http://localhost:4200

Die Optionen beantworten die Fragen, die ng new sonst stellt. Den Router brauchen wir erst in Lektion 2.4, Tests sind nicht Thema dieses Kurses. ng serve startet einen Entwicklungsserver, der bei jeder Änderung neu übersetzt und den Browser aktualisiert.

main.ts — der Einstiegspunkt

src/main.ts typescript 
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { App } from './app/app';

bootstrapApplication(App, appConfig)
  .catch((err) => console.error(err));

bootstrapApplication startet die App mit der Root-Komponente App. Angular sucht in index.html das Element <app-root> und zeichnet die Komponente dort hinein. appConfig enthält app-weite Einstellungen — im Moment nur eine bessere Fehlerausgabe in der Browser-Konsole:

src/app/app.config.ts typescript 
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners()],
};

Die Root-Komponente

src/app/app.ts typescript 
import { Component } from '@angular/core';
import { Flight } from './flight';
import { FLIGHTS } from './flights';

@Component({
  imports: [],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App {
  flights: Flight[] = FLIGHTS;
}
  • selector: 'app-root': Unter diesem HTML-Tag wird die Komponente eingesetzt.
  • imports: andere Komponenten, die im Template verwendet werden – noch keine.
  • templateUrl und styleUrl: Template und Styles in eigenen Dateien. app.css bleibt vorerst leer.
  • Die Eigenschaft flights der Klasse ist im Template direkt verfügbar.

Das Template

Zwei Dinge sind neu im Template:

  • Interpolation {{ ausdruck }} setzt einen Wert aus der Klasse als Text ein.
  • @for wiederholt einen Block für jedes Element eines Arrays — wie map() in React. track flight.id sagt Angular, woran es die Zeilen wiedererkennt (wie key in React). Weitere Kontrollstrukturen folgen in Lektion 1.4.
src/app/app.html html 
<div class="page-content">
  <h1 class="page-title">✈ FlugBoard Wien</h1>

  <table class="flight-table">
    <thead>
      <tr>
        <th>Flug</th>
        <th>Airline</th>
        <th>Typ</th>
        <th>Zeit</th>
        <th>Airport</th>
        <th>Status</th>
      </tr>

    <tbody>
      <!-- @for wiederholt die Zeile für jeden Flug -->

          <td>{{ flight.type }}</td>
          <td>{{ flight.scheduledTime }}</td>
          <td>{{ flight.airport }}</td>
          <td>{{ flight.status }}</td>
        </tr>
      }

  </table>
</div>

Projektschritt

Projektschritt 1.1

Statische Flugliste aufbauen

  1. Angular CLI installieren und das Projekt mit ng new anlegen (Abschnitt 4)
  2. src/styles.css durch das fertige Stylesheet ersetzen
  3. src/app/flight.ts und src/app/flights.ts anlegen
  4. app.ts und app.html wie in Abschnitt 5 anpassen — den Platzhalter-Inhalt von app.html komplett ersetzen
  5. ng serve starten und prüfen, ob alle Flüge in der Tabelle erscheinen

Häufige Fehler

ng: command not found

Die Angular CLI wurde nicht global installiert oder der npm-Bin-Pfad ist nicht im PATH.

Fix: npm install -g @angular/cli erneut ausführen. Danach im Terminal prüfen: echo $PATH sollte ~/.npm-global/bin oder den npm-Bin-Ordner enthalten. Alternativ: npx ng new flugboard verwenden.

Port 4200 bereits belegt

ng serve schreibt Address already in use und startet nicht.

Fix: ng serve --port 4201 oder den laufenden Prozess beenden: lsof -ti:4200 | xargs kill (macOS/Linux) bzw. im Task-Manager (Windows).

Cannot find name 'Flight'

Der TypeScript-Compiler findet das Interface nicht, weil der Import fehlt oder der Pfad falsch ist.

Fix: In app.ts den Import hinzufügen: import { Flight } from './flight';. Pfad prüfen: der Dateiname muss exakt flight.ts heißen (ohne .ts im Import).

Aufgaben

Aufgabe 1 Seed-Daten erweitern

Füge zwei weitere Flüge zu flights.ts hinzu: einen mit Status cancelled und einen mit Status departed. Stelle sicher, dass alle Pflichtfelder des Flight-Interface ausgefüllt sind und TypeScript keinen Fehler meldet.

Aufgabe 2 Tabellenspalte Terminal und Gate

Ergänze die HTML-Tabelle um die Spalten Terminal und Gate. Da gate optional ist, soll in der Zelle „—“ erscheinen, wenn kein Gate vorhanden ist. Verwende dazu den Nullish-Coalescing-Operator in der Interpolation: {{ flight.gate ?? '—' }}.

Aufgabe 3 Framework-Vergleich reflektieren

Du hast bereits React (oder ein anderes Framework) kennengelernt. Notiere drei konkrete Unterschiede zwischen Angular und deinem bisherigen Framework, die dir beim Lesen dieser Lektion aufgefallen sind. Gibt es etwas, das dir bei Angular intuitiver vorkommt? Was wirkt komplexer?

Bonus Angular DevTools erkunden

Installiere die Angular DevTools als Browser-Extension (Chrome). Starte ng serve und öffne die DevTools. Erkunde den Komponentenbaum: Welche Komponenten siehst du? Kannst du die Eigenschaft flights in der AppComponent sehen und live ändern?

5 Fragen · zum Aufklappen klicken

Frage 1 Was unterscheidet Angular grundsätzlich von React?

Erklärung: Bei React kombiniert man diese Teile aus externen Bibliotheken. Angular trifft viele Entscheidungen vorab – das hilft vor allem großen Teams.

Frage 2 Wie verhalten sich AngularJS (1.x) und Angular (ab Version 2)?

Erklärung: Wer heute „Angular“ sagt, meint Angular 2+. Anleitungen für AngularJS passen nicht.

Frage 3 Aus welchen Teilen besteht eine Angular-Komponente?

Erklärung: Der Decorator @Component verbindet Klasse, Template und Styles.

Frage 4 Wo gehören HTTP-Aufrufe und gemeinsamer State in Angular hin?

Erklärung: Komponenten kümmern sich um die Anzeige, Services um Logik und Daten.

Frage 5 Was bedeutet standalone bei modernen Angular-Komponenten?

Erklärung: Früher musste jede Komponente in einem NgModule registriert werden. Heute sind Komponenten standardmäßig standalone.
