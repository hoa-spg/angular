2 — Reactive Forms: das Formular in der Klasse

Terminal bash 
ng generate component add-flight-form
  • FormControl: ein Feld mit Startwert und Validatoren. nonNullable: true sorgt dafür, dass der Wert ein string bleibt und reset() auf den Startwert zurücksetzt statt auf null.
  • FormGroup: fasst die Felder unter Namen zusammen.
  • Validators: eingebaute Prüfungen wie required, pattern, minLength, min.
  • output<Omit<Flight, 'id'>>(): Das Formular meldet einen Flug ohne id – die vergibt App.
src/app/add-flight-form/add-flight-form.ts typescript 
import { Component, output } from '@angular/core';
import { FormControl, FormGroup, ReactiveFormsModule, Validators } from '@angular/forms';
import { Flight, FlightType } from '../flight';

@Component({
  imports: [ReactiveFormsModule],
  selector: 'app-add-flight-form',
  styleUrl: './add-flight-form.css',
  templateUrl: './add-flight-form.html',
})
export class AddFlightForm {
  added = output<Omit<Flight, 'id'>>();

  // Ein FormControl pro Feld: Startwert und Validatoren
  form = new FormGroup({
    flightNumber: new FormControl('', {
      nonNullable: true,
      validators: [Validators.required, Validators.pattern(/^[A-Za-z]{2}\d{3,4}$/)],
    }),
    airline: new FormControl('', { nonNullable: true, validators: Validators.required }),
    type: new FormControl<FlightType>('departure', { nonNullable: true }),
    scheduledTime: new FormControl('', { nonNullable: true, validators: Validators.required }),
    airport: new FormControl('', { nonNullable: true, validators: Validators.required }),
    terminal: new FormControl('T1', { nonNullable: true }),
    gate: new FormControl('', { nonNullable: true }),
  });

  // Fehler erst anzeigen, wenn das Feld schon einmal verlassen wurde
  showError(name: string): boolean {
    const control = this.form.get(name);
    return !!control && control.invalid && control.touched;
  }

  submit(): void {
    if (this.form.invalid) {
      this.form.markAllAsTouched(); // alle Fehler sichtbar machen
      return;
    }
    const value = this.form.getRawValue();
    this.added.emit({
      ...value,
      flightNumber: value.flightNumber.toUpperCase(),
      gate: value.gate || undefined,
      status: 'on-time',
    });
    this.form.reset(); // zurück auf die Startwerte
  }
}

Formular-Zustand

  • invalid / valid: Erfüllen alle Felder ihre Validatoren?
  • touched: Hat das Feld den Fokus schon einmal verloren? Fehler erst danach zu zeigen, wirkt freundlicher.
  • markAllAsTouched(): beim Absenden alle Felder als berührt markieren, damit alle Fehler erscheinen.
  • getRawValue() liefert die Werte als Objekt, reset() setzt das Formular zurück.

4 — Neue Flüge in die Liste aufnehmen

Bisher war flights ein normales Feld – die Liste hat sich nie geändert. Jetzt kommen Flüge dazu, also wird sie zum Signal (Lektion 1.3). filteredFlights liest sie mit this.flights() und rechnet automatisch neu.

update(fn) berechnet den neuen Wert aus dem alten. Wichtig: ein neues Array zurückgeben ([...list, neu]) statt mit push das alte zu verändern – nur so erkennt das Signal die Änderung.

src/app/app.ts typescript 
import { Component, computed, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { AddFlightForm } from './add-flight-form/add-flight-form';
import { AirportHeader } from './airport-header/airport-header';
import { FlightCard } from './flight-card/flight-card';
import { Flight, FlightType } from './flight';
import { FLIGHTS } from './flights';

@Component({
  imports: [FormsModule, AddFlightForm, AirportHeader, FlightCard],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App {
  // Signal, weil das Formular neue Flüge hinzufügt
  flights = signal<Flight[]>(FLIGHTS);
  selectedFlight = signal<Flight | null>(null);

  // Suchtext und Typfilter werden im Template geändert
  searchText = signal('');
  activeType = signal<'all' | FlightType>('all');

  // computed: wird neu berechnet, sobald sich ein gelesenes Signal ändert
  filteredFlights = computed(() => {
    const q = this.searchText().trim().toLowerCase();
    return this.flights()
      .filter((f) => this.activeType() === 'all' || f.type === this.activeType())
      .filter(
        (f) =>
          !q ||
          f.flightNumber.toLowerCase().includes(q) ||
          f.airline.toLowerCase().includes(q) ||
          f.airport.toLowerCase().includes(q),
      );
  });

  onFlightSelect(flight: Flight): void {
    this.selectedFlight.set(flight);
  }

  addFlight(data: Omit<Flight, 'id'>): void {
    // update: neuen Wert aus dem alten berechnen – neues Array statt push
    this.flights.update((list) => [...list, { ...data, id: Date.now() }]);
  }
}

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Can't bind to 'formGroup' since it isn't a known property of 'form'

ReactiveFormsModule fehlt im imports-Array der Formular-Komponente.

Fix: imports: [ReactiveFormsModule] – nicht FormsModule, das ist für ngModel.

Cannot find control with name: 'airlines'

Der Name in formControlName stimmt nicht mit dem Schlüssel in der FormGroup überein.

Fix: Schreibweise vergleichen: formControlName="airline" ↔ airline: new FormControl(…).

Neuer Flug erscheint nicht in der Liste

this.flights().push(neu) verändert das Array, aber das Signal bekommt davon nichts mit.

Fix: this.flights.update((list) => [...list, neu]) – ein neues Array erzeugen.

Aufgaben

3 Aufgaben + Bonus · zum Aufklappen klicken
Aufgabe 1 Formular ein- und ausblenden

Ein Button „+ Flug hinzufügen“ blendet das Formular ein und aus (Signal showForm, @if). Nach dem Hinzufügen schließt es sich.

Aufgabe 2 Genauere Fehlermeldungen

Unterscheide bei der Flugnummer „Pflichtfeld“ und „Falsches Format“. Welche Prüfung fehlschlägt, steht in form.controls.flightNumber.errors, z. B. { required: true } oder { pattern: … }.

Aufgabe 3 Button sperren

Sperre den Button, solange das Formular ungültig ist: [disabled]="form.invalid". Was ist für die Benutzerin besser – gesperrter Button oder Fehlermeldungen beim Absenden?

Bonus Eigener Validator

Ein Validator ist eine Funktion, die das Control bekommt und null (gültig) oder ein Fehler-Objekt liefert. Verbiete damit Wien als Ziel und hänge ihn an airport: validators: [Validators.required, noViennaValidator].

src/app/no-vienna-validator.ts typescript 
import { AbstractControl, ValidationErrors } from '@angular/forms';

// Ein Validator bekommt das Control und liefert null (gültig) oder ein Fehler-Objekt
export function noViennaValidator(control: AbstractControl): ValidationErrors | null {
  return control.value.includes('VIE') ? { noVienna: true } : null;
}

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was kennzeichnet Reactive Forms im Vergleich zu Template-Driven Forms?

Erklärung: Template-Driven eignet sich für einzelne Felder wie eine Suche, Reactive Forms für größere Formulare mit Validierung.

Frage 2 Wie verbindet man ein Eingabefeld mit dem Control airline der FormGroup?

Erklärung: Der Name muss exakt dem Schlüssel in der FormGroup entsprechen – sonst meldet Angular „Cannot find control with name“.

Frage 3 „Can't bind to 'formGroup' since it isn't a known property of 'form'“ – was fehlt?

Erklärung: FormsModule ist für ngModel, ReactiveFormsModule für [formGroup] und formControlName.

Frage 4 Wann sollte man eine Fehlermeldung zu einem Feld anzeigen?

Erklärung: So erscheinen Fehler nicht schon, bevor jemand überhaupt etwas eingegeben hat.

Frage 5 Ein neuer Flug erscheint nicht in der Liste nach this.flights().push(neu). Wie ist es richtig?

Erklärung: push verändert das bestehende Array, davon bekommt das Signal nichts mit. update mit einem neuen Array löst die Aktualisierung aus.
