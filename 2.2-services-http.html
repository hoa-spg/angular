Services & HTTP

Angular RxJS ca. 80 min Fortgeschritten

  • Einen Service mit @Injectable erstellen und per inject() verwenden

  • Den Unterschied zwischen Observable und Promise kennen und Observables subscriben
  • Loading-, Error- und Success-Zustände im Template sauber darstellen

Dependency Injection — Angulars eingebautes IoC-System

Dependency Injection (DI) ist ein Entwurfsmuster, bei dem Abhängigkeiten (Dependencies) nicht selbst instantiiert werden, sondern von außen injiziert werden. Angular hat DI tief ins Framework integriert: Es gibt einen Injektor-Baum, der Services bereitstellt und ihre Lebensdauer verwaltet.

providedIn: 'root' — Application-Singleton

Wenn ein Service mit providedIn: 'root' konfiguriert wird, erstellt Angular genau eine Instanz des Services für die gesamte Anwendung (Singleton-Pattern). Jede Komponente, die diesen Service anfordert, bekommt dieselbe Instanz.

inject() vs. Constructor-Injection

inject() vs. Constructor-Injection typescript 
// Moderner Ansatz: inject() (Angular 14+, empfohlen)
import { Component, inject, OnInit } from '@angular/core';
import { FlightApiService }          from '../services/flight-api.service';

export class AppComponent implements OnInit {
  private flightApi = inject(FlightApiService); // ← inject() Funktion

  ngOnInit(): void {
    this.flightApi.getFlights().subscribe(/* ... */);
  }
}

// Klassischer Ansatz: Constructor-Injection
export class AppComponent implements OnInit {
  constructor(private flightApi: FlightApiService) {}  // ← Konstruktor

  ngOnInit(): void {
    this.flightApi.getFlights().subscribe(/* ... */);
  }
}
ℹ
inject() — warum moderner?

inject() funktioniert auch in Funktionen und Custom Hooks (ähnlich React), die in einem Injektionskontext aufgerufen werden. Das erlaubt Muster wie Function-based Services und vereinfacht Code im Gegensatz zu langen Konstruktor- Parameterlisten. In neuen Angular-Projekten (17+) ist inject() die empfohlene Methode.

Services erstellen — @Injectable

Services sind normale TypeScript-Klassen, dekoriert mit @Injectable. Sie kapseln Geschäftslogik, HTTP-Aufrufe und gemeinsamen State, den mehrere Komponenten benötigen.

src/app/services/flight-api.service.ts typescript 
import { Injectable, inject }    from '@angular/core';
import { HttpClient }             from '@angular/common/http';
import { Observable }             from 'rxjs';
import { Flight }                 from '../models/flight';

@Injectable({
  providedIn: 'root',  // Application-Singleton
})
export class FlightApiService {
  private http = inject(HttpClient);

  // Basis-URL des Deno+Hono-Backends
  private readonly apiUrl = 'http://localhost:8000/api';

  /**
   * Alle Flüge abrufen
   */
  getFlights(): Observable<Flight[]> {
    return this.http.get<Flight[]>(`${this.apiUrl}/flights`);
  }

  /**
   * Einzelnen Flug nach ID abrufen
   */
  getFlightById(id: number): Observable<Flight> {
    return this.http.get<Flight>(`${this.apiUrl}/flights/${id}`);
  }

  /**
   * Neuen Flug anlegen
   */
  createFlight(flight: Omit<Flight, 'id'>): Observable<Flight> {
    return this.http.post<Flight>(`${this.apiUrl}/flights`, flight);
  }

  /**
   * Flug löschen
   */
  deleteFlight(id: number): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/flights/${id}`);
  }

  /**
   * Status eines Flugs aktualisieren
   */
  updateStatus(id: number, status: Flight['status']): Observable<Flight> {
    return this.http.patch<Flight>(`${this.apiUrl}/flights/${id}`, { status });
  }
}

HttpClient einrichten — provideHttpClient()

Der HttpClient muss in main.ts über provideHttpClient() bereitgestellt werden. Mit Angular 17 ist das die empfohlene Methode — kein Import von HttpClientModule mehr nötig.

src/app/app.config.ts typescript 
import { ApplicationConfig }         from '@angular/core';
import { provideRouter }             from '@angular/router';
import { provideHttpClient }         from '@angular/common/http';
import { provideAnimations }         from '@angular/platform-browser/animations';
import { routes }                    from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),      // ← HTTP-Client für die gesamte App
    provideAnimations(),
  ],
};

Observable — kurzer Einstieg (tiefer in Lektion 2.3)

Angulars HttpClient-Methoden geben Observables zurück, keine Promises. Ein Observable repräsentiert eine Sequenz von Werten über die Zeit. Um an die Daten zu kommen, muss man subscribe() aufrufen.

Eigenschaft Promise Observable
WerteEinmalig (1 Wert)Mehrfach (0-n Werte)
LazyStartet sofortStartet erst bei subscribe()
AbbrechenNicht cancellbarCancellbar via unsubscribe()
Operatorenthen/catch/finallymap, filter, switchMap, …
Mehrere WerteNeinJa (Streams, Polling)
Angular-IntegrationJa (toPromise / firstValueFrom)Nativ (HttpClient, Router)
Observable subscriben — Grundmuster typescript 
// Observable subscriben:
this.flightApi.getFlights().subscribe({
  next:     (flights) => { this.flights = flights; },
  error:    (err)     => { this.error   = err.message; },
  complete: ()        => { console.log('Stream beendet'); },
});

// Alternativ (nur next-Handler):
this.flightApi.getFlights().subscribe(flights => {
  this.flights = flights;
});

Das Drei-Zustands-Modell: Loading / Error / Success

Jede HTTP-Anfrage durchläuft drei Zustände. Diese sauber im Template darzustellen ist essenziell für eine gute User Experience.

AppComponent — Loading/Error/Success Pattern typescript 
import { Component, inject, OnInit }  from '@angular/core';
import { FlightApiService }           from './services/flight-api.service';
import { FlightListComponent }        from './components/flight-list/flight-list.component';
import { Flight }                     from './models/flight';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [FlightListComponent],
  template: `
    @if (isLoading) {
      <div class="loading-spinner">
        <span class="spinner"></span>
        Flugdaten werden geladen...
      </div>
    }

    @if (errorMessage) {
      <div class="error-banner">
        <strong>Fehler:</strong> {{ errorMessage }}
        <button (click)="loadFlights()">Erneut versuchen</button>
      </div>
    }

    @if (!isLoading && !errorMessage) {
      <app-flight-list [flights]="flights" />
    }
  `,
})
export class AppComponent implements OnInit {
  private flightApi = inject(FlightApiService);

  flights:      Flight[] = [];
  isLoading:    boolean  = false;
  errorMessage: string   = '';

  ngOnInit(): void {
    this.loadFlights();
  }

  loadFlights(): void {
    this.isLoading    = true;
    this.errorMessage = '';

    this.flightApi.getFlights().subscribe({
      next: (flights) => {
        this.flights   = flights;
        this.isLoading = false;
      },
      error: (err) => {
        this.errorMessage = `API nicht erreichbar: ${err.message}`;
        this.isLoading    = false;
      },
    });
  }
}
⚠
Memory Leak: Subscription nicht aufgeräumt

Wenn man subscribe() aufruft und die Subscription nie beendet, kann es zu Memory Leaks kommen — besonders wenn Komponenten zerstört und neu erstellt werden. Für HTTP-Anfragen ist das in der Regel kein Problem (HTTP-Observables completen nach einem Wert), aber für Intervalle oder unendliche Streams ist takeUntil(this.destroy$) oder die async-Pipe unverzichtbar. Lektion 2.3 behandelt dieses Thema ausführlich.

⚠
CORS-Probleme beim Entwickeln

Beim Aufruf von http://localhost:8000 aus der Angular-App auf http://localhost:4200 blockiert der Browser die Anfrage, wenn das Backend keinen Access-Control-Allow-Origin-Header setzt. Das Deno+Hono-Backend muss CORS explizit aktivieren:

Im Hono-Backend: app.use('*', cors({ origin: 'http://localhost:4200' })). Oder während der Entwicklung im Angular proxy.conf.json einen Proxy konfigurieren.

Lifecycle Hooks — ngOnInit()

Angular-Komponenten haben Lifecycle Hooks ähnlich wie React's useEffect. Der wichtigste für Datenladung ist ngOnInit(), der einmal nach der ersten Darbietung der Komponente aufgerufen wird.

Hook Zeitpunkt Verwendung
ngOnInit()Nach erstem RendernHTTP-Abruf, Initialisierung
ngOnChanges()Wenn Inputs sich ändernAuf neue @Input()-Werte reagieren
ngOnDestroy()Vor Zerstörung der KomponenteSubscriptions beenden, Cleanup
ngAfterViewInit()Nach View-InitialisierungDOM-Elemente via ViewChild ansprechen
ngOnInit + ngOnDestroy Grundmuster typescript 
import { Component, inject, OnInit, OnDestroy } from '@angular/core';
import { Subscription }                         from 'rxjs';
import { FlightApiService }                     from './services/flight-api.service';

export class FlightPageComponent implements OnInit, OnDestroy {
  private flightApi    = inject(FlightApiService);
  private subscription = new Subscription();

  ngOnInit(): void {
    // Subscription zur Sammlung hinzufügen
    this.subscription.add(
      this.flightApi.getFlights().subscribe(flights => {
        this.flights = flights;
      })
    );
  }

  ngOnDestroy(): void {
    // Alle Subscriptions beenden (verhindert Memory Leaks)
    this.subscription.unsubscribe();
  }
}

Projektschritt

Projektschritt 2.2

Statische Daten durch API ersetzen

Verbinde das FlugBoard mit dem Deno+Hono-Backend:

  1. provideHttpClient() in app.config.ts einbinden
  2. FlightApiService mit getFlights() und getFlightById() erstellen
  3. AppComponent oder FlightListComponent so anpassen, dass Daten via ngOnInit + subscribe geladen werden
  4. Loading-Spinner und Error-Banner im Template implementieren
  5. Backend starten (deno task dev) und Verbindung testen
  6. CORS im Backend konfigurieren, falls nötig

Häufige Fehler

NullInjectorError: No provider for HttpClient!

HttpClient ist nicht verfügbar, weil provideHttpClient() fehlt.

Fix: In app.config.ts unter providers provideHttpClient() einfügen.

HTTP-Request wird nicht ausgeführt (kein Netzwerk-Tab-Eintrag)

Observables sind lazy — ohne subscribe() passiert nichts.

Fix: this.flightApi.getFlights().subscribe(fn) aufrufen. Oder die async-Pipe im Template verwenden: {{ flights$ | async }}.

CORS-Fehler in der Browser-Konsole

„Access to fetch at '...' from origin '...' has been blocked by CORS policy“

Fix: Im Deno+Hono-Backend den CORS-Middleware einrichten: import { cors } from 'hono/cors'; app.use('*', cors());

TypeScript-Fehler: Typ unknown bei HTTP-Response

this.http.get('/api/flights') ohne Typparameter gibt Observable<unknown> zurück.

Fix: Typparameter angeben: this.http.get<Flight[]>('/api/flights'). TypeScript prüft dann, ob das API-Response-Format mit dem Interface übereinstimmt.

Aufgaben

Aufgabe 1 Flug löschen per HTTP DELETE

Implementiere in FlightApiService die Methode deleteFlight(id: number). Füge in FlightCardComponent einen „Löschen“-Button hinzu, der den Service aufruft und danach die Liste neu lädt. Nutze switchMap oder rufe nach dem Löschen einfach this.loadFlights() erneut auf.

Aufgabe 2 Loading-Skeleton statt Spinner

Ersetze den einfachen Spinner durch einen Skeleton-Loader: Eine Liste von 4 leeren Zeilen mit einem pulsierenden CSS-Effekt (@keyframes pulse), die während des Ladevorgangs angezeigt werden. Nutze @if (isLoading) und erstelle eine eigene SkeletonRowComponent.

Aufgabe 3 Auto-Refresh alle 30 Sekunden

Nutze setInterval(() => this.loadFlights(), 30_000) in ngOnInit, um die Flugliste automatisch zu aktualisieren. Stelle sicher, dass das Intervall in ngOnDestroy mit clearInterval gestoppt wird. Zeige einen kleinen Timestamp an, wann zuletzt aktualisiert wurde.

Aufgabe 4 async-Pipe kennenlernen

Refaktoriere loadFlights(): Anstatt manuell zu subscriben und this.flights zu setzen, erstelle eine flights$-Eigenschaft vom Typ Observable<Flight[]> und nutze die async-Pipe im Template: @if (flights$ | async; as flights) { ... }. Bonus Retry-Logik mit catchError + retry

Verwende RxJS-Operatoren, um bei einem HTTP-Fehler automatisch drei Mal zu wiederholen: this.http.get<Flight[]>(url).pipe(retry(3), catchError(e => of([]))). Erkunde die Dokumentation von retry, retryWhen und catchError und implementiere einen exponentiellen Backoff.
