Lektion 2.2 — Teil 2: Praxis & Fullstack

Services & HTTP

Angular RxJS ca. 80 min Fortgeschritten

Lernziele

  • Einen Service mit ng generate service anlegen
  • Abhängigkeiten mit inject() beziehen (Dependency Injection)
  • Mit HttpClient Daten laden und speichern
  • Observables mit subscribe starten und Antworten verarbeiten
  • Lade- und Fehlerzustand mit Signals anzeigen

1 — Das Backend

Bis jetzt kamen die Flüge aus flights.ts, und neue Flüge waren nach einem Neuladen wieder weg. Ab dieser Lektion speichert ein kleiner REST-Server die Flüge in einer SQLite-Datenbank – aufgebaut wie das Deno-Backend aus dem React-Kurs (Hono und Drizzle). Er liegt fertig im Beispielordner backend/; kopiere ihn neben den Ordner src/.

Terminal — Backend starten bash 
cd backend
deno task dev
# → FlugBoard API läuft auf http://localhost:8000
  • GET /api/flights liefert alle Flüge, POST /api/flights legt einen an.
  • Beim ersten Start legt das Backend die Datei flugboard.db an und füllt sie mit denselben acht Flügen wie bisher.
  • Es erlaubt Anfragen (CORS) nur von http://localhost:4200 – der Adresse von ng serve.

Die Datei src/app/flights.ts wird damit überflüssig und kann gelöscht werden.

2 — Ein Service für den Datenzugriff

Komponenten sollen sich um die Anzeige kümmern. Wie die Daten geladen werden, gehört in einen Service: eine Klasse, die Angular einmal erzeugt und allen Komponenten zur Verfügung stellt, die sie brauchen.

Terminal bash 
ng generate service flight-api
src/app/flight-api.ts typescript 
import { HttpClient } from '@angular/common/http';
import { Service, inject } from '@angular/core';
import { Observable } from 'rxjs';
import { Flight } from './flight';

const API_URL = 'http://localhost:8000/api/flights';

@Service()
export class FlightApi {
  // inject(): Angular liefert die eine, gemeinsame HttpClient-Instanz
  private http = inject(HttpClient);

  getFlights(): Observable<Flight[]> {
    return this.http.get<Flight[]>(API_URL);
  }

  addFlight(data: Omit<Flight, 'id'>): Observable<Flight> {
    return this.http.post<Flight>(API_URL, data);
  }
}
  • @Service() macht die Klasse zu einem Service, den es in der ganzen App genau einmal gibt.
  • inject(HttpClient) holt ein Objekt, das Angular bereitstellt – das ist Dependency Injection: Die Klasse erzeugt ihre Abhängigkeiten nicht selbst mit new, sondern bekommt sie geliefert.
  • HttpClient macht HTTP-Requests. get<Flight[]>(url) gibt an, welchen Typ die Antwort hat.

HttpClient bereitstellen

Damit inject(HttpClient) funktioniert, muss der HttpClient app-weit registriert sein – in app.config.ts:

src/app/app.config.ts typescript 
import { provideHttpClient } from '@angular/common/http';
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners(), provideHttpClient()],
};

3 — Observable: die Antwort kommt später

getFlights() liefert keine Flüge, sondern ein Observable – ein Versprechen, dass Daten kommen werden, ähnlich einem Promise. Zwei Unterschiede sind für den Anfang wichtig:

  • Der Request startet erst mit subscribe(…). Ohne subscribe passiert gar nichts.
  • subscribe bekommt ein Objekt mit next (Daten sind da) und error (Request fehlgeschlagen) – wie then und catch.

Observables können noch viel mehr, etwa mehrere Werte nacheinander liefern. Das ist Thema von Lektion 2.3.

4 — Daten beim Start laden

App holt sich den Service mit inject(FlightApi) und lädt die Flüge in ngOnInit. Das ist ein Lifecycle-Hook: eine Methode, die Angular einmal aufruft, sobald die Komponente erstellt ist – vergleichbar mit useEffect(…, []) in React. Die Klasse gibt mit implements OnInit an, dass sie diese Methode hat.

Weil die Antwort später kommt, startet flights als leere Liste. Dazu kommen zwei Signals für die anderen Zustände: loading und error. Alles, was sich hier ändert, ist ein Signal – nur so aktualisiert Angular die Anzeige, wenn die Antwort eintrifft.

src/app/app.ts typescript 
import { Component, OnInit, computed, inject, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { AddFlightForm } from './add-flight-form/add-flight-form';
import { AirportHeader } from './airport-header/airport-header';
import { FlightCard } from './flight-card/flight-card';
import { Flight, FlightType } from './flight';
import { FlightApi } from './flight-api';

@Component({
  imports: [FormsModule, AddFlightForm, AirportHeader, FlightCard],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App implements OnInit {
  private api = inject(FlightApi);

  // Startwert: leere Liste – die Flüge kommen vom Backend
  flights = signal<Flight[]>([]);
  loading = signal(true);
  error = signal('');
  selectedFlight = signal<Flight | null>(null);

  // Suchtext und Typfilter werden im Template geändert
  searchText = signal('');
  activeType = signal<'all' | FlightType>('all');

  // computed: wird neu berechnet, sobald sich ein gelesenes Signal ändert
  filteredFlights = computed(() => {
    const q = this.searchText().trim().toLowerCase();
    return this.flights()
      .filter((f) => this.activeType() === 'all' || f.type === this.activeType())
      .filter(
        (f) =>
          !q ||
          f.flightNumber.toLowerCase().includes(q) ||
          f.airline.toLowerCase().includes(q) ||
          f.airport.toLowerCase().includes(q),
      );
  });

  // ngOnInit: läuft einmal, wenn die Komponente erstellt ist
  ngOnInit(): void {
    // subscribe startet den Request und legt fest, was mit der Antwort passiert
    this.api.getFlights().subscribe({
      next: (flights) => {
        this.flights.set(flights);
        this.loading.set(false);
      },
      error: () => {
        this.error.set('Backend nicht erreichbar – läuft „deno task dev“?');
        this.loading.set(false);
      },
    });
  }

  onFlightSelect(flight: Flight): void {
    this.selectedFlight.set(flight);
  }

  addFlight(data: Omit<Flight, 'id'>): void {
    // Das Backend vergibt die id und liefert den gespeicherten Flug zurück
    this.api.addFlight(data).subscribe((flight) => {
      this.flights.update((list) => [...list, flight]);
    });
  }
}

Auch addFlight geht jetzt über das Backend. Die Antwort ist der gespeicherte Flug mit der vom Backend vergebenen id. Im Template zeigen zwei @if Lade- und Fehlerzustand über den Karten an:

src/app/app.html (Ausschnitt) html 
  @if (loading()) {
    <p class="page-meta">Flüge werden geladen …</p>
  }
  @if (error()) {
    <p class="form-error">{{ error() }}</p>
  }

Projektschritt

Projektschritt 2.2

Statische Daten durch das Backend ersetzen

  1. Den Ordner backend/ aus dem Beispiel übernehmen und mit deno task dev starten
  2. FlightApi mit ng generate service anlegen, provideHttpClient() in app.config.ts
  3. App: Service injizieren, Flüge in ngOnInit laden, loading und error als Signals
  4. addFlight über api.addFlight speichern; flights.ts löschen
  5. Testen: Einen Flug hinzufügen, die Seite neu laden – der Flug ist noch da. Backend stoppen und neu laden – die Fehlermeldung erscheint.

Häufige Fehler

4 Fehler · zum Aufklappen klicken
NullInjectorError: No provider for HttpClient!

provideHttpClient() fehlt in app.config.ts.

Fix: In providers eintragen und ng serve neu starten.

Kein Request im Netzwerk-Tab

this.api.getFlights() wird aufgerufen, aber nie abonniert.

Fix: Ein Observable startet erst mit .subscribe(…).

CORS-Fehler in der Browser-Konsole

Das Frontend läuft auf einem anderen Port als 4200, oder das Backend läuft nicht.

Fix: Backend starten und das Frontend mit ng serve auf Port 4200 betreiben.

Daten kommen an, die Anzeige bleibt leer

Im next-Callback wird ein normales Feld gesetzt (this.flights = flights) statt eines Signals.

Fix: this.flights.set(flights) – nur Signals lösen eine Aktualisierung aus.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Wie bezieht eine Komponente einen Service in modernem Angular?

Erklärung: Dependency Injection: Angular erzeugt den Service einmal und stellt ihn allen Komponenten zur Verfügung.

Frage 2 „NullInjectorError: No provider for HttpClient!“ – was fehlt?

Erklärung: Der HttpClient muss app-weit registriert sein, damit inject(HttpClient) funktioniert.

Frage 3 this.api.getFlights() wird aufgerufen, aber im Netzwerk-Tab erscheint kein Request. Warum?

Erklärung: Anders als ein Promise ist ein Observable „lazy“: Ohne Abonnent passiert nichts.

Frage 4 Was trifft auf ngOnInit zu?

Mehrere Antworten sind richtig.

Erklärung: ngOnInit ist ein Lifecycle-Hook: Angular ruft ihn einmal auf, sobald die Komponente bereit ist – ein guter Ort zum Laden der Daten. Man implementiert ihn als Methode ngOnInit() in der Komponentenklasse. Er ist weder Konstruktor noch Klick-Event.

Frage 5 Die Daten kommen an, aber die Anzeige bleibt leer. Im next-Callback steht this.flights = flights. Was ist falsch?

Erklärung: Werte, die sich zur Laufzeit ändern, gehören in ein Signal.
