Lektion 1.3 — Teil 1: Grundlagen

Datenbindung & Events

Angular ca. 75 min Grundlagen

Lernziele

  • Alle vier Datenbindungstypen sicher und korrekt einsetzen können
  • FormsModule einbinden und [(ngModel)] für Two-Way-Binding nutzen
  • Event-Typisierung verstehen: $event, InputEvent, MouseEvent
  • Getter als reaktiven, berechneten State einsetzen (Angular-Äquivalent zu useMemo)
  • Ein Suchfeld und einen Typ-Filter für das FlugBoard implementieren
  • Change Detection und wann sie ausgelöst wird verstehen

Die 4 Bindungstypen — ausführlich

1. Interpolation {{ }}

Wertet einen JavaScript-Ausdruck aus und fügt das Ergebnis als Text in das DOM ein. Sicher gegen XSS: Angular escaped automatisch. Kann einfache Ausdrücke enthalten, aber keine Statements (if, for, Zuweisungen sind nicht erlaubt).

Interpolation Beispiele html 
<!-- Einfache Eigenschaft: -->
<span>{{ flight.flightNumber }}</span>

<!-- Berechneter Ausdruck: -->
<span>{{ flight.airline.toUpperCase() }}</span>

<!-- Ternary-Operator: -->
<span>{{ flight.type === 'departure' ? 'Abflug' : 'Ankunft' }}</span>

<!-- Nullish Coalescing: -->
<span>{{ flight.gate ?? 'kein Gate' }}</span>

<!-- Template-Ausdruck (kein Statement erlaubt!): -->
<span>{{ count++ }}</span>  <!-- ← FEHLER! Seiteneffekte verboten -->

2. Property-Binding [property]="ausdruck"

Bindet einen Ausdruck an eine DOM-Eigenschaft oder eine Komponent-Input-Eigenschaft. Die eckigen Klammern signalisieren: „Dieser Wert wird dynamisch berechnet.“ Ohne Klammern würde Angular den Wert als literal String übergeben.

Property-Binding Beispiele html 
<!-- DOM-Eigenschaft: -->
<img [src]="flight.airlineLogo" [alt]="flight.airline">
<button [disabled]="flight.status === 'departed'">Details</button>

<!-- CSS-Klasse dynamisch setzen: -->
<div [class.delayed]="flight.status === 'delayed'">
<div [class]="'status-' + flight.status">

<!-- Inline-Style dynamisch: -->
<span [style.color]="flight.status === 'cancelled' ? 'red' : 'inherit'">

<!-- Input einer Kindkomponente: -->
<app-flight-card [flight]="currentFlight"></app-flight-card>

<!-- ACHTUNG: Unterschied zu Interpolation: -->
<button disabled="true">     <!-- String "true" → Button IMMER disabled -->
<button [disabled]="true">   <!-- Boolean true  → Button disabled -->
<button [disabled]="false">  <!-- Boolean false → Button enabled -->

3. Event-Binding (event)="handler($event)"

Hört auf DOM-Events (click, input, submit, keyup, ...) oder benutzerdefinierte Ereignisse von Kindkomponenten. $event enthält das native Event-Objekt.

Event-Binding Beispiele – Template html 
<button (click)="onDeleteFlight(flight)">Löschen</button>
<input (input)="onSearchInput($event)">
<form (submit)="onFormSubmit($event)">
<input (keyup.enter)="onEnterPressed()">  <!-- Angular Key-Filter -->
Event-Binding Beispiele – Klasse typescript 
export class FlightListComponent {
  flights: Flight[] = FLIGHTS;

  onDeleteFlight(flight: Flight): void {
    this.flights = this.flights.filter(f => f.id !== flight.id);
  }

  onSearchInput(event: Event): void {
    // Typsicherheit: event.target ist EventTarget, kein HTMLInputElement
    const input = event.target as HTMLInputElement;
    this.searchTerm = input.value;
  }
}

4. Two-Way-Binding [(ngModel)]="eigenschaft"

Syntaktischer Zucker für die Kombination aus Property-Binding und Event-Binding. [(ngModel)] entspricht [ngModel]="term" (ngModelChange)="term = $event". Benötigt das FormsModule im imports-Array.

FormsModule — Two-Way-Binding aktivieren

⚠
FormsModule vergessen — häufigster Fehler!

[(ngModel)] funktioniert nur, wenn FormsModule im imports-Array der Komponente steht. Ohne diesen Import erscheint der Fehler: „Can't bind to 'ngModel' since it isn't a known property of 'input'.“

FlugBoard-Suchfeld mit [(ngModel)] typescript 
import { Component }  from '@angular/core';
import { FormsModule } from '@angular/forms';   // ← Pflicht für ngModel!
import { Flight }      from '../../models/flight';
import { FLIGHTS }     from '../../data/flights';

@Component({
  selector: 'app-flight-list',
  standalone: true,
  imports: [FormsModule],  // ← hier eintragen
  template: `
    <div class="controls">
      <input
        type="text"
        [(ngModel)]="searchTerm"
        placeholder="Flugnummer, Airline, Flughafen..."
        class="search-input"
      >
      <span class="result-count">{{ filteredFlights.length }} Treffer</span>
    </div>

    <table class="flight-table">
      <thead>
        <tr>
          <th>Flug</th><th>Airline</th><th>Zeit</th><th>Status</th>
        </tr>
      </thead>
      <tbody>
        @for (flight of filteredFlights; track flight.id) {
          <tr>
            <td>{{ flight.flightNumber }}</td>
            <td>{{ flight.airline }}</td>
            <td>{{ flight.scheduledTime }}</td>
            <td>{{ flight.status }}</td>
          </tr>
        } @empty {
          <tr>
            <td colspan="4" class="empty-state">Keine Flüge gefunden.</td>
          </tr>
        }
      </tbody>
    </table>
  `,
})
export class FlightListComponent {
  flights: Flight[]  = FLIGHTS;
  searchTerm: string = '';

  // Getter = reaktiver computed State (kein useMemo nötig)
  get filteredFlights(): Flight[] {
    const term = this.searchTerm.toLowerCase().trim();
    if (!term) return this.flights;
    return this.flights.filter(f =>
      f.flightNumber.toLowerCase().includes(term) ||
      f.airline.toLowerCase().includes(term)      ||
      f.airport.toLowerCase().includes(term)
    );
  }
}

Typ-Filter mit Buttons

Zusätzlich zum Suchfeld wollen wir per Button zwischen Alle, Abflüge und Ankünfte filtern können. Das Muster ist: eine Zustandsvariable hält den aktiven Filter, der Getter kombiniert beide Filter, Property-Binding auf [class.active] markiert den aktiven Button.

Typ-Filter — Komponente komplett typescript 
import { Component }  from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Flight, FlightType } from '../../models/flight';
import { FLIGHTS }            from '../../data/flights';

type FilterType = 'all' | FlightType;

@Component({
  selector: 'app-flight-list',
  standalone: true,
  imports: [FormsModule],
  template: `
    <div class="controls">
      <input
        type="text"
        [(ngModel)]="searchTerm"
        placeholder="Suche..."
      >
      <div class="type-filter">
        <button
          [class.active]="typeFilter === 'all'"
          (click)="typeFilter = 'all'"
        >Alle</button>
        <button
          [class.active]="typeFilter === 'departure'"
          (click)="typeFilter = 'departure'"
        >Abflüge</button>
        <button
          [class.active]="typeFilter === 'arrival'"
          (click)="typeFilter = 'arrival'"
        >Ankünfte</button>
      </div>
      <p class="result-info">
        {{ filteredFlights.length }} von {{ flights.length }} Flügen
      </p>
    </div>

    @for (flight of filteredFlights; track flight.id) {
      <div class="flight-row">
        <strong>{{ flight.flightNumber }}</strong> – {{ flight.airline }}
      </div>
    } @empty {
      <p class="empty">Keine Flüge für diese Auswahl.</p>
    }
  `,
})
export class FlightListComponent {
  flights: Flight[]   = FLIGHTS;
  searchTerm: string  = '';
  typeFilter: FilterType = 'all';

  get filteredFlights(): Flight[] {
    const term = this.searchTerm.toLowerCase().trim();

    return this.flights.filter(f => {
      // Typ-Filter
      if (this.typeFilter !== 'all' && f.type !== this.typeFilter) {
        return false;
      }
      // Suchtext-Filter
      if (term) {
        return (
          f.flightNumber.toLowerCase().includes(term) ||
          f.airline.toLowerCase().includes(term)      ||
          f.airport.toLowerCase().includes(term)
        );
      }
      return true;
    });
  }
}

Getter als reaktiver State — das Angular-Muster

In React würde man useMemo() verwenden, um eine berechnete Liste nicht bei jedem Render neu zu berechnen. In Angular ist das Muster anders: TypeScript-Getter werden bei jedem Change-Detection-Durchlauf aufgerufen und liefern den aktuellen Wert.

Konzept React Angular
Lokaler Stateconst [x, setX] = useState(v)x = v (Klasseneigenschaft)
State ändernsetX(newVal)this.x = newVal
Berechneter WertuseMemo(() => compute(x), [x])get computed() { return compute(this.x); }
SeiteneffekteuseEffect(() => {}, [dep])ngOnInit(), ngOnChanges()
Input (Props)function Comp({ prop }: Props)@Input() prop: Type
Output (Callback)const cb = props.onEvent@Output() ev = new EventEmitter()
ℹ
Getter und Performance

Angular ruft Getter bei jedem Change-Detection-Durchlauf auf. Für einfache Berechnungen (Filter, Sort) ist das vollkommen in Ordnung. Für sehr teure Berechnungen: entweder ChangeDetectionStrategy.OnPush verwenden (reduziert Checks drastisch) oder die Filterlogik in einen Signal oder ein computed() verlagern (Angular 16+ Signals API).

Change Detection — wann aktualisiert Angular die View?

Angular hört automatisch auf alle asynchronen Ereignisse: Browser-Events (Clicks, Inputs), HTTP-Antworten, setTimeout/setInterval-Callbacks — und läuft danach durch den gesamten Komponentenbaum, um zu prüfen, ob sich etwas geändert hat (Dirty Checking). Das passiert dank der Zone.js-Bibliothek, die Angular im Hintergrund patcht.

Default vs. OnPush

  • Default: Nach jedem Event wird der gesamte Baum geprüft. Einfach und sicher, aber bei großen Apps langsam.
  • OnPush: Eine Komponente wird nur geprüft, wenn (a) ein neues Input-Objekt ankommt (neue Referenz!), (b) ein Output-Event gefeuert hat oder (c) manuell markForCheck() aufgerufen wurde.
✓
Unveränderlichkeit und OnPush

Mit OnPush muss man darauf achten, Arrays und Objekte immer durch neue Referenzen zu ersetzen statt sie zu mutieren. this.flights.push(newFlight) würde bei OnPush kein Re-Render auslösen. Richtig: this.flights = [...this.flights, newFlight]. Dasselbe Prinzip wie in React.

Projektschritt

Projektschritt 1.3

Suchfeld + Typfilter + Trefferzaehler

Erweitere FlightListComponent um vollständige Filterfunktionalität:

  1. FormsModule in imports einbinden
  2. Suchfeld mit [(ngModel)]="searchTerm" einbauen
  3. Drei Filter-Buttons (Alle / Abflüge / Ankünfte) mit [class.active] und (click) implementieren
  4. Getter filteredFlights schreiben, der beide Filter kombiniert
  5. Trefferzaehler anzeigen: „X von Y Flügen“
  6. Empty-State mit @empty für den Fall, dass nichts gefunden wird

Häufige Fehler

Can't bind to 'ngModel' since it isn't a known property of 'input'

Das FormsModule fehlt im imports-Array der Standalone-Komponente.

Fix: import { FormsModule } from '@angular/forms'; und imports: [FormsModule] in die betroffene Komponente eintragen.

Filter funktioniert, aber Array-Mutation wird nicht angezeigt

Bei this.flights.push(f) bleibt die View leer/veraltet, wenn OnPush aktiv ist.

Fix: this.flights = [...this.flights, f] verwenden, um eine neue Array-Referenz zu erzeugen. Angular erkennt dann die Veränderung.

Getter wird bei jedem Tastendruck mehrfach aufgerufen

Das ist normales Angular-Verhalten bei Default-Change-Detection. Der Getter wird bei jedem CD-Durchlauf aufgerufen (auch wenn keine Änderung vorliegt), was bei teuren Operationen zu Performance-Problemen führen kann.

Fix (kurzfristig): ChangeDetectionStrategy.OnPush setzen. Fix (modern): Angular Signals (signal(), computed()) verwenden — diese berechnen nur bei tatsächlicher Änderung neu.

$event hat Typ any beim Input-Event

(input)="onInput($event)" übergibt Event, nicht InputEvent<HTMLInputElement>. event.target.value ist dann ein Typfehler.

Fix: In der Methode casten: const val = (event.target as HTMLInputElement).value;. Oder besser: [(ngModel)] statt manuellen Input-Events verwenden — dann ist kein Casten nötig.

Aufgaben

Aufgabe 1 Status-Filter ergänzen

Füge einen weiteren Filter hinzu, der nach Status filtert. Implementiere ein <select>-Element mit [(ngModel)] und den Optionen Alle Status, On-Time, Delayed, Boarding, Cancelled. Kombiniere den Status-Filter mit dem bestehenden Suchfeld- und Typ-Filter.

Aufgabe 2 Sortierung nach Zeit

Ergänze den filteredFlights-Getter um eine optionale Sortierung nach scheduledTime aufsteigend oder absteigend. Verwende einen weiteren Button-Toggle (Zeit ↑ / Zeit ↓) und das Zustandsvariable sortAsc: boolean = true.

Aufgabe 3 Suchfeld zurücksetzen

Füge einen „Zurücksetzen“-Button hinzu, der sichtbar ist wenn searchTerm !== '' oder typeFilter !== 'all'. Ein Klick setzt beide Variablen auf ihren Defaultwert zurück. Nutze [class.visible] oder @if für die Sichtbarkeit.

Aufgabe 4 Verspätungs-Indikator

Zeige in jeder Flugzeile einen visuellen Verspätungs-Indikator an. Wenn flight.expectedTime vorhanden ist und später als flight.scheduledTime, berechne die Verspätung in Minuten und zeige „+X min“ an. Nutze dafür eine Methode getDelay(flight: Flight): number | null.

Bonus Signals statt Getter

Lies die Angular-Dokumentation zu Signals (Angular 16+) und refaktoriere den searchTerm und typeFilter zu signal()-Variablen. Nutze computed() statt eines Getters für filteredFlights. Beobachte den Unterschied im Profiler.
