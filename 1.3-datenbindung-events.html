Lektion 1.3 — Teil 1: Grundlagen

Datenbindung & Events

Angular ca. 75 min Grundlagen

Lernziele

  • Die vier Bindungstypen unterscheiden und einsetzen
  • Ein Eingabefeld mit [(ngModel)] an ein Signal binden
  • CSS-Klassen mit [class.name] bedingt setzen
  • Abgeleitete Werte mit computed berechnen
  • Verstehen, wie Signals die Aktualisierung der Anzeige steuern

1 — Die vier Bindungstypen

Drei Arten, Klasse und Template zu verbinden, kennst du schon aus den Lektionen 1.1 und 1.2. Neu ist die vierte:

TypSyntaxRichtungBeispiel im FlugBoard
Interpolation{{ ausdruck }}Klasse → Template{{ flight().airline }}
Property-Binding[eigenschaft]="ausdruck"Klasse → Template[flight]="flight"
Event-Binding(ereignis)="anweisung"Template → Klasse(click)="selected.emit(flight())"
Two-Way-Binding[(ngModel)]="signal"beide Richtungen[(ngModel)]="searchText"

2 — Suchfeld mit Two-Way-Binding

Der Suchtext ist ein Wert, den die Benutzerin im Template ändert – also ein Signal wie selectedFlight aus Lektion 1.2:

src/app/app.ts (Ausschnitt) typescript 
searchText = signal('');

[(ngModel)]="searchText" verbindet das Eingabefeld in beide Richtungen: Tippt man, setzt Angular das Signal; ändert der Code das Signal, ändert sich das Feld. Die Schreibweise [( )] („Banana in a Box“) kombiniert Property- und Event-Binding.

ngModel gehört zum FormsModule. Wie eine Komponente muss es im imports-Array stehen, sonst kennt das Template ngModel nicht.

3 — Typfilter mit Buttons

Der Typfilter ist ebenfalls ein Signal. Sein Typ erlaubt nur drei Werte:

src/app/app.ts (Ausschnitt) typescript 
activeType = signal<'all' | FlightType>('all');
  • (click)="activeType.set('departure')": Event-Binding ruft direkt set auf – eine eigene Methode ist nicht nötig.
  • [class.active]="activeType() === 'departure'": Property-Binding auf eine einzelne CSS-Klasse. Ist der Ausdruck wahr, bekommt der Button die Klasse active.

4 — computed: abgeleitete Werte

Die angezeigte Liste hängt von searchText und activeType ab. computed(() => …) erzeugt ein Signal, dessen Wert aus anderen Signals berechnet wird. Angular merkt sich, welche Signals die Funktion liest, und rechnet nur neu, wenn sich eines davon ändert – wie useMemo in React, nur ohne Abhängigkeitsliste.

src/app/app.ts typescript 
import { Component, computed, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { AirportHeader } from './airport-header/airport-header';
import { FlightCard } from './flight-card/flight-card';
import { Flight, FlightType } from './flight';
import { FLIGHTS } from './flights';

@Component({
  imports: [FormsModule, AirportHeader, FlightCard],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App {
  flights: Flight[] = FLIGHTS;
  selectedFlight = signal<Flight | null>(null);

  // Suchtext und Typfilter werden im Template geändert
  searchText = signal('');
  activeType = signal<'all' | FlightType>('all');

  // computed: wird neu berechnet, sobald sich ein gelesenes Signal ändert
  filteredFlights = computed(() => {
    const q = this.searchText().trim().toLowerCase();
    return this.flights
      .filter((f) => this.activeType() === 'all' || f.type === this.activeType())
      .filter(
        (f) =>
          !q ||
          f.flightNumber.toLowerCase().includes(q) ||
          f.airline.toLowerCase().includes(q) ||
          f.airport.toLowerCase().includes(q),
      );
  });

  onFlightSelect(flight: Flight): void {
    this.selectedFlight.set(flight);
  }
}

Im Template ersetzt filteredFlights() die bisherige Liste; dazu kommen Suchfeld, Filter-Buttons und die Trefferzahl:

src/app/app.html html 
<div class="page-content">
  <app-airport-header airportName="Wien" />

  <div class="toolbar">
    <!-- Two-Way-Binding: Eingabe und Signal bleiben synchron -->
    <input
      class="search-input"
      [(ngModel)]="searchText"
      placeholder="Flug, Airline, Airport ..."
    />

    <!-- Property-Binding auf eine CSS-Klasse + Event-Binding -->
    <div class="type-filter">
      <button [class.active]="activeType() === 'all'" (click)="activeType.set('all')">Alle</button>
      <button [class.active]="activeType() === 'departure'" (click)="activeType.set('departure')">
        Abflüge
      </button>
      <button [class.active]="activeType() === 'arrival'" (click)="activeType.set('arrival')">
        Ankünfte
      </button>
    </div>

    <span class="page-meta">{{ filteredFlights().length }} Treffer</span>
  </div>

  @if (selectedFlight()) {
    <div class="selected-info">
      <strong>Ausgewählt:</strong>
      {{ selectedFlight()?.flightNumber }} – {{ selectedFlight()?.airline }}
    </div>
  }

  <div class="card-grid">
    @for (flight of filteredFlights(); track flight.id) {
      <app-flight-card [flight]="flight" (selected)="onFlightSelect($event)" />
    }
  </div>
</div>

5 — Wie Angular die Anzeige aktualisiert

Neue Angular-Projekte arbeiten mit Signals: Wird ein Signal geändert, weiß Angular genau, welche Templates es lesen, und zeichnet nur diese neu. Ein Signal, das sich ändert, zieht automatisch alle davon abhängigen computed-Werte nach – searchText → filteredFlights → Trefferzahl und Kartenraster.

⚠
Veränderliche Werte immer als Signal

Ein normales Feld wie flights darf es geben, solange es sich nicht ändert. Werte, die sich zur Laufzeit ändern, gehören in ein Signal – sonst bekommt Angular die Änderung nicht zuverlässig mit.

Projektschritt

Projektschritt 1.3

Suchfeld, Typfilter und Trefferzähler

  1. In app.ts die Signals searchText und activeType anlegen und FormsModule importieren
  2. filteredFlights mit computed berechnen
  3. Im Template die Toolbar mit Suchfeld ([(ngModel)]), drei Filter-Buttons und Trefferzahl ergänzen
  4. @for über filteredFlights() statt flights laufen lassen

Häufige Fehler

Can't bind to 'ngModel' since it isn't a known property of 'input'

FormsModule fehlt im imports-Array der Komponente.

Fix: import { FormsModule } from '@angular/forms'; und imports: [FormsModule, …].

Signal im Template ohne Klammern

@for (flight of filteredFlights; …) meldet, dass ein Signal nicht durchlaufen werden kann.

Fix: Den Wert lesen: filteredFlights(). Nur bei [(ngModel)]="searchText" steht das Signal selbst, ohne Klammern – dort braucht Angular das Signal, um es setzen zu können.

computed rechnet nicht neu

Die Liste reagiert nicht auf den Filter, weil die Funktion den Wert eines normalen Feldes statt eines Signals liest.

Fix: Alles, worauf computed reagieren soll, muss ein Signal sein und mit () gelesen werden.

Aufgaben

Aufgabe 1 Suchfeld zurücksetzen

Ein Button „✕“ neben dem Suchfeld setzt searchText auf '' – das Feld leert sich dank Two-Way-Binding mit.

Aufgabe 2 Status-Filter

Ergänze ein <select> mit allen Status-Werten und der Option „alle“. Binde es mit [(ngModel)] an ein neues Signal und berücksichtige es in filteredFlights.

Aufgabe 3 Sortierung nach Zeit

Ein Button schaltet zwischen aufsteigender und absteigender Sortierung nach scheduledTime um. Die Sortierung gehört ins computed; kopiere das Array vorher mit [...liste], weil sort das Original verändert.

Bonus Verspätungen zählen

Zeige neben der Trefferzahl an, wie viele der gefilterten Flüge verspätet sind – als eigenes computed, das auf filteredFlights aufbaut.
