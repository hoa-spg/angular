Listen, Filter & Pipes

Angular ca. 65 min Grundlagen

Lernziele

  • Die neue Control-Flow-Syntax (@for, @if, @else, @empty, @switch) sicher einsetzen
  • Den Zweck von track verstehen und korrekt anwenden
  • Eingebaute Pipes (date, uppercase, titlecase, number) im Template nutzen
  • Eine eigene Pure Pipe mit @Pipe und PipeTransform implementieren
  • Eine wiederverwendbare FlightStatusBadge-Komponente mit Pipes bauen

Angular 17+: Die neue Control-Flow-Syntax

Angular 17 hat die bisher als „strukturelle Direktiven“ implementierten Kontrollstrukturen *ngFor und *ngIf durch eine native Template-Syntax ersetzt. Die neue Syntax ist direkter im Compiler verankert — kein Import von CommonModule oder NgIf/NgFor mehr nötig.

Vergleich: Alt vs. Neu

Zweck Alt (Angular < 17) Neu (Angular 17+)
Bedingtes Rendern*ngIf="cond"@if (cond) { ... }
If/Else*ngIf="c; else tpl" + #tpl@if (c) { } @else { }
Liste rendern*ngFor="let x of list"@for (x of list; track x.id) { }
Leere ListeSeparates *ngIf@empty { } innerhalb @for
Switch[ngSwitch] + *ngSwitchCase@switch (val) { @case (x) { } }

@for — Listen rendern

@for mit track und @empty html 
@for (flight of filteredFlights; track flight.id) {
  <app-flight-card [flight]="flight" />
} @empty {
  <p class="empty-state">Keine Flüge gefunden.</p>
}

<!-- Lokale Variablen im @for-Block: -->
@for (flight of flights; track flight.id; let i = $index) {
  <div>{{ i + 1 }}. {{ flight.flightNumber }}</div>
}
<!-- $index  – 0-basierter Index -->
<!-- $first  – true beim ersten Element -->
<!-- $last   – true beim letzten Element -->
<!-- $even   – true bei geraden Indizes -->
<!-- $odd    – true bei ungeraden Indizes -->
<!-- $count  – Gesamtanzahl der Elemente -->

@if / @else if / @else

@if mit @else if und @else html 
@if (flight.status === 'boarding') {
  <span class="badge boarding">Boarding</span>
} @else if (flight.status === 'delayed') {
  <span class="badge delayed">Verspätet</span>
} @else if (flight.status === 'cancelled') {
  <span class="badge cancelled">Storniert</span>
} @else {
  <span class="badge">{{ flight.status }}</span>
}

@switch

@switch für Status-Varianten html 
@switch (flight.status) {
  @case ('on-time')   { <span class="badge on-time">Pünktlich</span> }
  @case ('delayed')   { <span class="badge delayed">Verspätet</span> }
  @case ('boarding')  { <span class="badge boarding">Boarding</span> }
  @case ('departed')  { <span class="badge departed">Abgeflogen</span> }
  @case ('landed')    { <span class="badge landed">Gelandet</span> }
  @case ('cancelled') { <span class="badge cancelled">Storniert</span> }
  @default            { <span class="badge">{{ flight.status }}</span> }
}

track — das Äquivalent zu key in React

Die track-Expression in @for teilt Angular mit, wie es Listenelemente eindeutig identifizieren soll. Das ist notwendig, damit Angular beim Neurendern einer Liste nicht alle DOM-Elemente neu erstellt, sondern nur die geänderten aktualisiert.

track korrekt verwenden html 
<!-- Gut: eindeutige ID -->
@for (flight of flights; track flight.id) { ... }

<!-- Gut: falls kein id-Feld vorhanden (Fallback, weniger optimal) -->
@for (item of items; track $index) { ... }

<!-- Gut: zusammengesetzte ID -->
@for (flight of flights; track flight.flightNumber + flight.scheduledTime) { ... }

<!-- Schlecht: kein track – Angular zeigt Warnung und kann DOM nicht optimieren -->
@for (flight of flights) { ... }  <!-- ← TypeScript-Fehler ab Angular 17! -->
ℹ
track ist in Angular 17 Pflicht

Seit Angular 17 ist track in @for verpflichtend. Das ist eine Designentscheidung, um Performance-Probleme durch fehlendes Tracking zu verhindern — anders als in React, wo key optional (aber empfohlen) ist.

Eingebaute Pipes — Datentransformation im Template

Pipes sind reine Transformationsfunktionen für Template-Ausdrücke. Sie werden mit dem Pipe-Operator | verknüpft und können Argumente mit :argument erhalten.

Pipes in imports[] registrieren typescript 
// Pipes müssen einzeln in imports[] der Komponente stehen:
import { DatePipe, UpperCasePipe, LowerCasePipe,
         TitleCasePipe, DecimalPipe, CurrencyPipe,
         SlicePipe, JsonPipe } from '@angular/common';
Eingebaute Pipes im Einsatz html 
<!-- uppercase / lowercase / titlecase -->
{{ flight.airline | uppercase }}    <!-- → "AUSTRIAN AIRLINES" -->
{{ flight.status  | lowercase }}    <!-- → "on-time" -->
{{ 'wien flughafen' | titlecase }}  <!-- → "Wien Flughafen" -->

<!-- date: Datumsformatierung (locale-sensitiv) -->
{{ today | date:'dd.MM.yyyy' }}                    <!-- → "15.03.2024" -->
{{ today | date:'EEEE, d. MMMM y':'':'de' }}       <!-- → "Freitag, 15. März 2024" -->

<!-- number: Zahlenformatierung ({minInt}.{minFrac}-{maxFrac}) -->
{{ 1234567.89 | number:'1.2-2' }}  <!-- → "1,234,567.89" -->

<!-- currency: Währungsformatierung -->
{{ price | currency:'EUR':'symbol':'1.2-2':'de' }}  <!-- → "1.234,56 €" -->

<!-- slice: Array/String slicen -->
{{ flight.flightNumber | slice:0:2 }}  <!-- → "OS" (Airline-Code) -->

<!-- json: Objekt als JSON ausgeben (nützlich für Debugging) -->
{{ flight | json }}

Pipes in Standalone-Komponenten importieren typescript

Custom Pipes — eigene Transformationen

Wenn keine eingebaute Pipe passt, kann man eigene implementieren. Eine Pipe ist eine Klasse, die PipeTransform implementiert und mit @Pipe dekoriert wird. Sie sollte pure sein (kein Seiteneffekt, gleiche Eingabe liefert immer gleiche Ausgabe), damit Angular sie effizient cachen kann.

src/app/pipes/status-color.pipe.ts typescript 
import { Pipe, PipeTransform } from '@angular/core';
import { FlightStatus }        from '../models/flight';

/**
 * Gibt die CSS-Klasse für einen Flugstatus zurück.
 * Verwendung: [class]="flight.status | statusColor"
 */
@Pipe({
  name: 'statusColor',
  standalone: true,  // Standalone Pipe (Angular 14+)
  pure: true,        // Default: true; Angular cached den Output
})
export class StatusColorPipe implements PipeTransform {
  transform(status: FlightStatus): string {
    const colorMap: Record<FlightStatus, string> = {
      'on-time':   'badge-green',
      'delayed':   'badge-orange',
      'boarding':  'badge-blue',
      'departed':  'badge-gray',
      'landed':    'badge-teal',
      'cancelled': 'badge-red',
    };
    return colorMap[status] ?? 'badge-default';
  }
}
src/app/pipes/status-label.pipe.ts typescript 
import { Pipe, PipeTransform } from '@angular/core';
import { FlightStatus }        from '../models/flight';

/**
 * Gibt den deutschen Label-Text für einen Flugstatus zurück.
 * Verwendung: {{ flight.status | statusLabel }}
 */
@Pipe({
  name: 'statusLabel',
  standalone: true,
  pure: true,
})
export class StatusLabelPipe implements PipeTransform {
  private readonly labels: Record<FlightStatus, string> = {
    'on-time':   'Pünktlich',
    'delayed':   'Verspätet',
    'boarding':  'Boarding',
    'departed':  'Abgeflogen',
    'landed':    'Gelandet',
    'cancelled': 'Gestrichen',
  };

  transform(status: FlightStatus): string {
    return this.labels[status] ?? status;
  }
}

Vollständige Flugliste mit @for, @if und Pipes

flight-list.component.ts (komplett) typescript 
import { Component }                   from '@angular/core';
import { FormsModule }                  from '@angular/forms';
import { UpperCasePipe }                from '@angular/common';
import { FlightStatusBadgeComponent }   from '../flight-status-badge/flight-status-badge.component';
import { Flight }                       from '../../models/flight';
import { FLIGHTS }                      from '../../data/flights';

@Component({
  selector: 'app-flight-list',
  standalone: true,
  imports: [FormsModule, UpperCasePipe, FlightStatusBadgeComponent],
  template: `
    <div class="controls">
      <input [(ngModel)]="searchTerm" placeholder="Suche...">
    </div>

    <table class="flight-table">
      <thead>
        <tr>
          <th>Flug</th>
          <th>Airline</th>
          <th>Typ</th>
          <th>Zeit (geplant)</th>
          <th>Status</th>
          <th>Flughafen</th>
          <th>Terminal</th>
        </tr>
      </thead>
      <tbody>
        @for (flight of filteredFlights; track flight.id; let i = $index) {
          <tr [class.even-row]="i % 2 === 0">
            <td><strong>{{ flight.flightNumber }}</strong></td>
            <td>{{ flight.airline }}</td>
            <td>
              @if (flight.type === 'departure') {
                <span>▲ Abflug</span>
              } @else {
                <span>▼ Ankunft</span>
              }
            </td>
            <td>
              {{ flight.scheduledTime }}
              @if (flight.expectedTime) {
                <span class="delayed-time">(erw. {{ flight.expectedTime }})</span>
              }
            </td>
            <td>
              <app-flight-status-badge [status]="flight.status" />
            </td>
            <td>{{ flight.airport }}</td>
            <td>{{ flight.terminal }}{{ flight.gate ? ' / ' + flight.gate : '' }}</td>
          </tr>
        } @empty {
          <tr>
            <td colspan="7" class="empty-state">
              Kein Flug für „{{ searchTerm }}“ gefunden.
            </td>
          </tr>
        }
      </tbody>
    </table>
  `,
})
export class FlightListComponent {
  flights: Flight[]  = FLIGHTS;
  searchTerm: string = '';

  get filteredFlights(): Flight[] {
    const term = this.searchTerm.toLowerCase().trim();
    if (!term) return this.flights;
    return this.flights.filter(f =>
      f.flightNumber.toLowerCase().includes(term) ||
      f.airline.toLowerCase().includes(term)      ||
      f.airport.toLowerCase().includes(term)
    );
  }
}
✓
Pipe vs. Methode — wann welches?

Pipes für reine Datentransformationen im Template (Formatierung, Label-Mapping, Farb-Mapping). Angular kann pure Pipes cachen. Methoden für komplexe Logik mit Seiteneffekten oder mehreren Parametern. Vermeide teure Methodenaufrufe direkt im Template (jeder Change-Detection-Durchlauf ruft sie auf) — nutze stattdessen Getter oder berechnete Eigenschaften.

Häufige Fehler

track in @for vergessen

Angular 17 macht track obligatorisch. Ein fehlender track-Ausdruck führt zu einem Kompilierfehler.

Fix: Immer track item.id (oder track $index als Fallback) angeben: @for (x of list; track x.id) { }.

Pipe nicht importiert — Template-Fehler

InvalidPipeArgument oder „The pipe 'statusColor' could not be found“, weil die Pipe nicht im imports-Array steht.

Fix: Pipe-Klasse im imports-Array der Komponente eintragen, die sie nutzt: imports: [StatusColorPipe].

Impure Pipe wird zu oft aufgerufen

Eine Pipe mit pure: false wird bei jedem Change-Detection-Durchlauf aufgerufen — auch wenn der Eingabewert unverändert ist. Das kann Performance- Probleme verursachen.

Fix: Immer pure: true (der Default) verwenden, wenn möglich. Impure Pipes nur dann einsetzen, wenn die Transformation von externem State abhängt, der sich außerhalb des Eingabewerts ändern kann (z.B. aktueller Timestamp).

Aufgabe 1 FlightTypePipe implementieren

Erstelle eine Pipe FlightTypePipe, die 'departure' in „▲ Abflug“ und 'arrival' in „▼ Ankunft“ umwandelt. Verwende sie im FlightCard-Template statt des bisherigen @if-Blocks.

Aufgabe 2 Verzögerungsminuten mit Pipe

Erstelle eine Pipe DelayMinutesPipe, die ein Flight-Objekt entgegennimmt und die Verzögerung in Minuten als String zurückgibt (z.B. „+25 min“ oder „—“ wenn keine Verzögerung). Verwende sie in der Flugtabelle.

Aufgabe 3 Zebra-Streifen mit $index

Nutze die lokale Variable $index im @for-Block, um jeder zweiten Zeile die CSS-Klasse row-even zuzuweisen. Verwende [class.row-even]="$index % 2 === 0". Definiere passende Styles direkt in der Komponente (styles oder styleUrl).

Bonus Pipe mit Argument: Zeitformat

Erstelle eine Pipe FlightTimePipe, die einen HH:MM-String entgegennimmt. Per optionalem Argument :format soll sie entweder „HH:MM Uhr“ (default) oder „H.MM Uhr“ (Format 'short') ausgeben. Implementiere die Pipe mit PipeTransform und Argumentübergabe via transform(value: string, format = 'long').
