Lektion 1.2 — Teil 1: Grundlagen

Komponenten & Templates

Angular ca. 70 min Einsteiger

Lernziele

  • Komponenten mit der CLI anlegen und in anderen Komponenten verwenden
  • Daten mit input() von der Eltern- an die Kind-Komponente übergeben
  • Ereignisse mit output() an die Eltern-Komponente melden
  • Property-Binding [ ] und Event-Binding ( ) einsetzen
  • Veränderliche Werte in einem Signal speichern

1 — Eine Komponente anlegen

In Lektion 1.1 stand alles in der Root-Komponente App. Jetzt zerlegen wir die Oberfläche in kleinere Bausteine: eine Kopfzeile AirportHeader und eine Karte FlightCard pro Flug. Neue Komponenten legt die CLI an:

Terminal bash 
ng generate component airport-header
ng generate component flight-card

Jede Komponente bekommt einen eigenen Ordner mit drei Dateien, z. B. flight-card/flight-card.ts, .html und eine leere .css. Der Decorator sieht aus wie bei App:

  • selector: das HTML-Tag, mit dem die Komponente in anderen Templates eingesetzt wird, z. B. <app-flight-card />.
  • imports: alle Komponenten, die dieses Template verwendet. Wer <app-flight-card> verwenden will, muss FlightCard hier eintragen.

2 — input(): Werte von der Eltern-Komponente

Komponenten bekommen Daten von außen über Inputs – wie Props in React. input.required<string>() legt einen Pflicht-Input vom Typ string an. Im Template liest man den Wert mit Klammern: airportName(), denn ein Input ist eine Funktion, die den aktuellen Wert liefert.

src/app/airport-header/airport-header.ts typescript 
import { Component, input } from '@angular/core';

@Component({
  imports: [],
  selector: 'app-airport-header',
  styleUrl: './airport-header.css',
  templateUrl: './airport-header.html',
})
export class AirportHeader {
  // Input: Der Wert kommt von der Eltern-Komponente
  airportName = input.required<string>();
}
src/app/airport-header/airport-header.html html 
<h1 class="page-title">✈ FlugBoard {{ airportName() }}</h1>

Die Eltern-Komponente setzt den Input wie ein HTML-Attribut: <app-airport-header airportName="Wien" />. Das ist ein fester Text.

Property-Binding: Werte aus der Klasse übergeben

Soll der Wert aus einer Variablen kommen, setzt man den Namen in eckige Klammern: [flight]="flight". Rechts steht dann ein TypeScript-Ausdruck, kein Text. Die FlightCard bekommt so ein ganzes Flight-Objekt:

src/app/flight-card/flight-card.html html 
<article class="flight-card" (click)="selected.emit(flight())">
  <div class="flight-card-head">
    <span class="flight-num">{{ flight().flightNumber }}</span>
    <span class="status-badge status-{{ flight().status }}">{{ flight().status }}</span>
  </div>
  <p class="flight-card-airline">{{ flight().airline }}</p>
  <p class="flight-card-meta">
    {{ flight().type === 'departure' ? '↑' : '↓' }} {{ flight().airport }}
  </p>
  <p class="flight-card-meta">{{ flight().scheduledTime }} · {{ flight().terminal }}</p>
</article>
  • class="status-badge status-{{ flight().status }}": Interpolation funktioniert auch in Attributen. Bei delayed entsteht die CSS-Klasse status-delayed.
  • Im Ausdruck dürfen JavaScript-Operatoren stehen, etwa der Bedingungsoperator ? : für den Pfeil.

3 — output(): Ereignisse an die Eltern-Komponente

Daten fließen über Inputs nach unten. Will das Kind etwas melden – „ich wurde angeklickt“ –, verwendet es einen Output. In React wäre das eine Callback-Prop wie onSelect.

src/app/flight-card/flight-card.ts typescript 
import { Component, input, output } from '@angular/core';
import { Flight } from '../flight';

@Component({
  imports: [],
  selector: 'app-flight-card',
  styleUrl: './flight-card.css',
  templateUrl: './flight-card.html',
})
export class FlightCard {
  flight = input.required<Flight>();
  // Output: meldet der Eltern-Komponente, dass die Karte angeklickt wurde
  selected = output<Flight>();
}
  • output<Flight>() legt ein Ereignis an, das einen Flight mitliefert.
  • (click)="selected.emit(flight())" im Template: Runde Klammern binden ein DOM-Ereignis (Event-Binding). Beim Klick löst die Karte selected mit ihrem Flug aus.

4 — Komposition in App: das erste Signal

App setzt die Bausteine zusammen. Auf den Output der Karte hört sie mit Event-Binding: (selected)="onFlightSelect($event)". $event ist der Wert, den die Karte mit emit geschickt hat.

Der ausgewählte Flug ist der erste Wert im FlugBoard, der sich ändert. Damit Angular dann die Anzeige aktualisiert, speichern wir ihn in einem Signal:

  • signal<Flight | null>(null) erzeugt ein Signal mit Startwert null – vergleichbar mit useState.
  • selectedFlight.set(flight) setzt einen neuen Wert, selectedFlight() liest ihn – im Template genauso wie in der Klasse.
src/app/app.ts typescript 
import { Component, signal } from '@angular/core';
import { AirportHeader } from './airport-header/airport-header';
import { FlightCard } from './flight-card/flight-card';
import { Flight } from './flight';
import { FLIGHTS } from './flights';

@Component({
  imports: [AirportHeader, FlightCard],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App {
  flights: Flight[] = FLIGHTS;
  // Signal: Angular aktualisiert die Anzeige, sobald sich der Wert ändert
  selectedFlight = signal<Flight | null>(null);

  onFlightSelect(flight: Flight): void {
    this.selectedFlight.set(flight);
  }
}

Im Template zeigt @if einen Block nur an, wenn die Bedingung erfüllt ist – hier erst, wenn ein Flug ausgewählt wurde. ?. ist nötig, weil TypeScript den Wert weiterhin als Flight | null sieht. Die Tabelle aus Lektion 1.1 wird zu einem Raster aus Karten:

src/app/app.html html 
<div class="page-content">
  <app-airport-header airportName="Wien" />

  @if (selectedFlight()) {
    <div class="selected-info">
      <strong>Ausgewählt:</strong>
      {{ selectedFlight()?.flightNumber }} – {{ selectedFlight()?.airline }}
    </div>
  }

  <div class="card-grid">
    @for (flight of flights; track flight.id) {
      <app-flight-card [flight]="flight" (selected)="onFlightSelect($event)" />
    }
  </div>
</div>

Häufige Fehler

'app-flight-card' is not a known element

Die Komponente wird im Template verwendet, steht aber nicht im imports-Array der nutzenden Komponente.

Fix: In app.ts importieren und eintragen: imports: [AirportHeader, FlightCard].

Input ohne Klammern gelesen

Im Template steht {{ flight.flightNumber }} – TypeScript meldet, dass es flightNumber auf dem Input nicht gibt.

Fix: Inputs und Signals sind Funktionen: {{ flight().flightNumber }}.

Signal direkt zugewiesen

this.selectedFlight = flight überschreibt das Signal selbst mit einem Flug – TypeScript meldet einen Typfehler.

Fix: Den Wert mit this.selectedFlight.set(flight) setzen.

Aufgaben

Aufgabe 1 Ausgewählte Karte hervorheben

Gib FlightCard einen zweiten Input isSelected (Typ boolean, Standardwert false: input(false)). Setze damit die Klasse is-selected über Property-Binding: [class.is-selected]="isSelected()", und lege in flight-card.css eine Regel für .is-selected an (z. B. ein farbiger Rahmen). Die Styles in dieser Datei gelten nur für die Karte.

Aufgabe 2 Auswahl aufheben

Ergänze in der Auswahl-Box einen Button „✕“, der selectedFlight wieder auf null setzt.

Aufgabe 3 FlightCount-Komponente

Lege eine Komponente FlightCount mit den Inputs count (Zahl) und label (Text) an, die z. B. „8 Flüge“ anzeigt. Setze sie unter die Kopfzeile.

Bonus Kopfzeile mit Untertitel

Gib AirportHeader einen optionalen Input subtitle (input<string>()). Nur wenn er gesetzt ist, erscheint darunter eine Zeile mit der Klasse page-meta.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Wie übergibt die Eltern-Komponente einen Wert aus einer Variablen an das Input flight?

Erklärung: Mit eckigen Klammern (Property-Binding) steht rechts ein TypeScript-Ausdruck. Ohne Klammern wäre es der feste Text „flight“.

Frage 2 Im Template steht {{ flight.flightNumber }}, und TypeScript meldet einen Fehler. Warum?

Erklärung: flight = input.required<Flight>() liefert eine Funktion, die den aktuellen Wert zurückgibt.

Frage 3 Wie meldet eine Kind-Komponente ein Ereignis an die Eltern-Komponente?

Erklärung: Die Eltern-Komponente hört mit Event-Binding darauf: (selected)="onFlightSelect($event)". In React wäre das eine Callback-Prop.

Frage 4 Die Fehlermeldung lautet 'app-flight-card' is not a known element. Was fehlt?

Erklärung: Standalone-Komponenten müssen alles importieren, was ihr Template verwendet.

Frage 5 Wie setzt man einen neuen Wert in das Signal selectedFlight?

Erklärung: Eine Zuweisung würde das Signal selbst überschreiben. Gelesen wird mit selectedFlight(), gesetzt mit set (oder update).
