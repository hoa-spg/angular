Komponenten-Anatomie — @Component im Detail

Jede Angular-Komponente ist eine TypeScript-Klasse, dekoriert mit @Component. Der Decorator konfiguriert Angular, wie die Komponente verhalten, dargestellt und eingebunden werden soll.

Vollständige @Component-Optionen typescript 
@Component({
  // Pflichtfelder:
  selector: 'app-flight-card',  // HTML-Tag dieser Komponente

  // Standalone-API (Angular 14+):
  standalone: true,
  imports: [                    // andere Komponenten/Direktiven/Pipes
    CommonModule,               // bei Verwendung von @if/@for (nicht nötig ab Angular 17)
    FlightStatusBadgeComponent, // eigene Kindkomponenten müssen hier stehen!
  ],

  // Template – entweder inline oder als Datei:
  template: `<div>Inline HTML</div>`,
  // oder:
  templateUrl: './flight-card.component.html',

  // Styles – inline oder als Datei:
  styles: [`
    :host { display: block; }
    .card { border: 1px solid var(--border); }
  `],
  // oder:
  styleUrl: './flight-card.component.css',

  // Change Detection (optional, Standard: Default):
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class FlightCardComponent {
  // Klassenlogik hier
}
⚠
Häufigster Anfängerfehler: Vergessenes Import

Bei Standalone-Komponenten muss jede genutzte Kind-Komponente im imports-Array stehen. Fehlt ein Eintrag, erscheint der Fehler „'app-flight-card' is not a known element“. Das gilt auch für eingebaute Direktiven wie NgClass oder Pipes wie DatePipe — wenn du sie in deinem Template nutzt, müssen sie importiert sein.

Die 4 Bindungstypen im Überblick

Typ Syntax Richtung Beispiel
Interpolation {{ ausdruck }} Klasse → DOM (Text) {{ flight.flightNumber }}
Property-Binding [eigenschaft]="ausdruck" Klasse → DOM (Attribut) [class.delayed]="isDelayed"
Event-Binding (ereignis)="handler($event)" DOM → Klasse (click)="onSelect(flight)"
Two-Way-Binding [(ngModel)]="eigenschaft" Bidirektional [(ngModel)]="searchTerm"

Property-Binding vs. Interpolation

Interpolation ({{ }}) wird für Textinhalt verwendet. Property-Binding ([]) wird für HTML-Attribute und DOM-Eigenschaften verwendet. Ein häufiger Fehler ist, src="{{ url }}" statt [src]="url" zu verwenden — bei src funktioniert beides, aber Property-Binding ist korrekter und notwendig bei boolschen Attributen wie disabled.

Template-Bindungen im Einsatz typescript 
// In der Komponentenklasse:
export class FlightCardComponent {
  @Input({ required: true }) flight!: Flight;

  isDelayed(): boolean {
    return this.flight.status === 'delayed';
  }
}
flight-card.component.html (Template) html 
<!-- Interpolation: -->
<span>{{ flight.flightNumber }}</span>

<!-- Property-Binding (setzt CSS-Klasse dynamisch): -->
<div [class.delayed]="flight.status === 'delayed'">

<!-- Property-Binding auf disabled: -->
<button [disabled]="flight.status === 'departed'">Details</button>

<!-- Event-Binding: -->
<button (click)="onDetailsClick()">Details</button>

<!-- Kombination – dynamische Klasse auf Basis des Status: -->
<span [class]="'badge badge-' + flight.status">
  {{ flight.status }}
</span>

@Input() — Props von Eltern an Kind übergeben

In Angular heissen „Props“ Inputs. Sie werden mit dem @Input()-Decorator an einer Klasseneigenschaft markiert. Seit Angular 16 kann man required: true angeben, damit Angular beim Vergessen des Inputs einen Fehler wirft.

src/app/components/flight-card/flight-card.component.ts typescript 
import { Component, Input }   from '@angular/core';
import { Flight }             from '../../models/flight';

@Component({
  selector: 'app-flight-card',
  standalone: true,
  imports: [],
  template: `
    <div class="flight-card" [class.delayed]="flight.status === 'delayed'">
      <div class="flight-number">{{ flight.flightNumber }}</div>
      <div class="airline">{{ flight.airline }}</div>
      <div class="route">
        {{ flight.type === 'departure' ? '➔' : '➓' }}
        {{ flight.airport }}
      </div>
      <div class="time">
        {{ flight.scheduledTime }}
        @if (flight.expectedTime) {
          <span class="expected">(erw. {{ flight.expectedTime }})</span>
        }
      </div>
      <div class="meta">
        {{ flight.terminal }}
        @if (flight.gate) {
          • Gate {{ flight.gate }}
        }
      </div>
    </div>
  `,
})
export class FlightCardComponent {
  // required: true → Fehler wenn kein Wert übergeben wird
  @Input({ required: true }) flight!: Flight;
}

Verwendung im Eltern-Template

Parent-Komponente: flight-list.component.ts typescript 
import { Component }           from '@angular/core';
import { FlightCardComponent } from './flight-card/flight-card.component';
import { Flight }              from '../../models/flight';
import { FLIGHTS }             from '../../data/flights';

@Component({
  selector: 'app-flight-list',
  standalone: true,
  imports: [FlightCardComponent],  // ← Kindkomponente muss hier stehen!
  template: `
    <section class="flight-list">
      <h2>Flüge ({{ flights.length }})</h2>
      @for (flight of flights; track flight.id) {
        <app-flight-card [flight]="flight" />
      }
    </section>
  `,
})
export class FlightListComponent {
  flights: Flight[] = FLIGHTS;
}

@Output() & EventEmitter — Ereignisse an Eltern senden

Während @Input() Daten nach unten (Eltern → Kind) überträgt, senden @Output()-Eigenschaften Ereignisse nach oben (Kind → Eltern). Das ist äquivalent zu Callback-Props in React.

flight-card.component.ts — mit @Output typescript 
import { Component, Input, Output, EventEmitter } from '@angular/core';
import { Flight } from '../../models/flight';

@Component({
  selector: 'app-flight-card',
  standalone: true,
  imports: [],
  template: `
    <div class="flight-card" (click)="onCardClick()">
      <div class="flight-number">{{ flight.flightNumber }}</div>
      <div class="airline">{{ flight.airline }}</div>
      <button (click)="onSelectClick($event)">Auswählen</button>
    </div>
  `,
})
export class FlightCardComponent {
  @Input({ required: true }) flight!: Flight;

  // EventEmitter mit dem Typ des emittierten Werts typisieren:
  @Output() flightSelected = new EventEmitter<Flight>();

  onCardClick(): void {
    this.flightSelected.emit(this.flight);
  }

  onSelectClick(event: MouseEvent): void {
    event.stopPropagation(); // verhindert Bubble zum (click) auf dem div
    this.flightSelected.emit(this.flight);
  }
}
Parent-Template: auf @Output lauschen html 
<app-flight-card
  [flight]="flight"
  (flightSelected)="onFlightSelected($event)"
/>
FlightListComponent-Klasse typescript 
selectedFlight: Flight | null = null;

onFlightSelected(flight: Flight): void {
  this.selectedFlight = flight;
  console.log('Ausgewählt:', flight.flightNumber);
}

Komponentenkomposition — FlugBoard aufteilen

Die gesamte FlugBoard-App wird in klar getrennte Komponenten aufgeteilt. Die Elternkomponente verwaltet die Daten (Smart Component), die Kindkomponenten präsentieren sie (Dumb/Presentational Components).

Komponentenhierarchie FlugBoard bash 
AppComponent (Root)
├── AirportHeaderComponent       ← Flughafen-Name, Datum/Uhrzeit
├── SearchBarComponent           ← Suchfeld (kommt in Lektion 1.3)
└── FlightListComponent          ← Verwaltet Flug-Array
    └── FlightCardComponent      ← Einzelner Flug (erhält Flight via @Input)

AirportHeaderComponent

src/app/components/airport-header/airport-header.component.ts typescript 
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-airport-header',
  standalone: true,
  imports: [],
  template: `
    <header class="airport-header">
      <div class="airport-title">
        <span class="icon">✈</span>
        <h1>{{ airportName }}</h1>
      </div>
      <div class="airport-meta">
        <span class="iata">{{ iataCode }}</span>
        <span class="date">{{ currentDate }}</span>
      </div>
    </header>
  `,
})
export class AirportHeaderComponent {
  @Input() airportName = 'Flughafen Wien';
  @Input() iataCode    = 'VIE';

  get currentDate(): string {
    return new Date().toLocaleDateString('de-AT', {
      weekday: 'long',
      year:    'numeric',
      month:   'long',
      day:     'numeric',
    });
  }
}

src/app/app.component.ts typescript 
import { Component }              from '@angular/core';

React JSX vs. Angular Template — Vergleich

Konzept React (JSX) Angular (Template)
Props an Kind<Card flight={f} /><app-card [flight]="f" />
Callback-Prop<Card onSelect={fn} /><app-card (selected)="fn($event)" />
Bedingtes Rendern{show && <Elem />}@if (show) { <elem /> }
Liste rendern{list.map(i => <Item key={i.id} />)}@for (i of list; track i.id) { <app-item /> }
Textinterpolation{value}{{ value }}
Dynamische KlasseclassName={active ? 'on' : ''}[class.on]="active"

Projektschritt

Projektschritt 1.2

FlugBoard in Komponenten aufteilen

Refaktoriere das Ergebnis aus Lektion 1.1 in eine saubere Komponentenstruktur:

  1. Erstelle FlightCardComponent mit @Input({ required: true }) flight und einem Template, das alle Felder zeigt
  2. Erstelle FlightListComponent, die flights: Flight[] verwaltet und FlightCardComponent per @for rendert
  3. Erstelle AirportHeaderComponent mit den Inputs airportName und iataCode
  4. Verdrahte alles in AppComponent zusammen
  5. Ergänze @Output() flightSelected auf FlightCardComponent; gib den selektierten Flug in der Konsole aus

Häufige Fehler

'app-flight-card' is not a known element

Die FlightCardComponent wurde im Template verwendet, aber nicht im imports-Array der nutzenden Komponente eingetragen.

Fix: In der FlightListComponent (oder welche Komponente auch immer <app-flight-card> verwendet) die Klasse importieren: imports: [FlightCardComponent].

Property has no initializer and is not definitely assigned

TypeScript beschwert sich, dass @Input() flight!: Flight das Ausrufezeichen fehlt. Ohne ! meldet TypeScript einen Fehler, weil die Eigenschaft im Konstruktor nicht initialisiert wird.

Fix: Das Non-null-Assertion-Ausrufezeichen hinzufügen: flight!: Flight. Bei required: true garantiert Angular, dass der Wert immer gesetzt ist.

EventEmitter gibt den falschen Typ aus

@Output() flightSelected = new EventEmitter() ohne Typparameter liefert EventEmitter<any> — der Elternteil bekommt $event: any.

Fix: Typ explizit angeben: new EventEmitter<Flight>(). Dann wird $event im Eltern-Template automatisch als Flight typisiert.

Aufgaben

Aufgabe 1 Typ-Badge in FlightCard einbauen

Ergänze FlightCardComponent um ein visuelles Element, das ▲ Abflug oder ▼ Ankunft anzeigt, je nachdem ob flight.type === 'departure' oder 'arrival'. Nutze dafür Property-Binding auf eine CSS-Klasse ([class.departure]="...").

Aufgabe 2 Selektion im AppComponent anzeigen

Wenn auf eine FlightCard geklickt wird, soll der ausgewählte Flug unterhalb der Liste in einer kleinen Detail-Box angezeigt werden. Implementiere das @Output()-Pattern vollständig: flightSelected in der Card, Handler im AppComponent, Anzeige mit @if (selectedFlight).

Aufgabe 3 FlightCount-Komponente

Erstelle eine kleine Komponente FlightCountComponent, die @Input() count: number und @Input() label: string empfängt und „X Flüge“ anzeigt. Verwende sie im Header der FlightListComponent.

Bonus ChangeDetectionStrategy.OnPush

Setze changeDetection: ChangeDetectionStrategy.OnPush in der FlightCardComponent. Was ändert sich? Öffne die Angular DevTools und beobachte, wie oft die Komponente neu gerendert wird.
