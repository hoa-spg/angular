Fullstack FlugBoard

Angular RxJS Deno + Hono ca. 120 min Fortgeschritten

Lernziele

  • Den Angular Router einrichten und Routen definieren
  • Seiten mit <router-outlet>, routerLink und Router.navigate wechseln
  • Routen-Parameter als input() empfangen

  • Den Aufbau des fertigen Fullstack-FlugBoards erklären

1 — Client-Side Routing

Bisher hat das FlugBoard genau eine Ansicht. Jetzt bekommt jeder Flug eine eigene Detailseite mit eigener URL, z. B. /flight/2. Der Angular Router wechselt die angezeigte Komponente passend zur URL – ohne die Seite neu vom Server zu laden. Das Prinzip kennst du aus React Router:

React RouterAngular Router
<Route path="/flight/:id" element={…} />Eintrag in routes: { path: 'flight/:id', … }
<Outlet /><router-outlet />
<Link to="/"><a routerLink="/">
useNavigate()inject(Router).navigate(…)
useParams()Routen-Parameter als input()

2 — Den Router einrichten

Das Projekt wurde in Lektion 1.1 ohne Router angelegt. Wir ergänzen ihn von Hand. Die Routen stehen in einer eigenen Datei:

src/app/app.routes.ts typescript 
import { Routes } from '@angular/router';
import { FlightBoard } from './flight-board/flight-board';

export const routes: Routes = [
  { path: '', component: FlightBoard },
  {
    path: 'flight/:id',
    // Lazy Loading: der Code der Detailseite wird erst beim ersten Aufruf geladen
    loadComponent: () => import('./flight-detail/flight-detail').then((m) => m.FlightDetail),
  },
  { path: '**', redirectTo: '' },
];
  • path: '' ist die Startseite, flight/:id eine Route mit Parameter: :id passt auf jeden Wert, etwa /flight/2.
  • path: '**' fängt alle unbekannten URLs ab und leitet zur Startseite um.
  • loadComponent lädt die Detailseite erst, wenn sie gebraucht wird (Abschnitt 5).

In app.config.ts wird der Router mit diesen Routen bereitgestellt:

src/app/app.config.ts typescript 
import { provideHttpClient } from '@angular/common/http';
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideHttpClient(),
    // withComponentInputBinding: Routen-Parameter wie :id kommen als input() an
    provideRouter(routes, withComponentInputBinding()),
  ],
};

4 — Die Detailseite

Die Detailseite braucht den Wert von :id. Dank withComponentInputBinding() kommt er als Input mit demselben Namen an: id = input.required<string>(). Werte aus der URL sind immer Strings, deshalb Number(this.id()). Der Service bekommt eine Methode für einen einzelnen Flug:

src/app/flight-api.ts (Ausschnitt) typescript 
  getFlight(id: number): Observable<Flight> {
    return this.http.get<Flight>(`${API_URL}/${id}`);
  }
src/app/flight-detail/flight-detail.ts typescript 
import { Component, OnInit, inject, input, signal } from '@angular/core';
import { RouterLink } from '@angular/router';
import { Flight } from '../flight';
import { FlightApi } from '../flight-api';
import { StatusLabelPipe } from '../status-label-pipe';

@Component({
  imports: [RouterLink, StatusLabelPipe],
  selector: 'app-flight-detail',
  styleUrl: './flight-detail.css',
  templateUrl: './flight-detail.html',
})
export class FlightDetail implements OnInit {
  private api = inject(FlightApi);

  // Wert des Routen-Parameters :id aus der URL /flight/:id
  id = input.required<string>();

  flight = signal<Flight | null>(null);
  error = signal('');

  ngOnInit(): void {
    this.api.getFlight(Number(this.id())).subscribe({
      next: (flight) => this.flight.set(flight),
      error: () => this.error.set('Flug nicht gefunden.'),
    });
  }
}

Im Template führt routerLink="/" zurück zum Board – wie ein normaler Link, aber ohne die Seite neu zu laden. RouterLink muss dazu im imports-Array stehen. @else if unterscheidet Fehler und Ladezustand.

5 — Lazy Loading

Mit loadComponent landet die Detailseite in einer eigenen Datei, die der Browser erst beim ersten Aufruf von /flight/… lädt. Große Apps starten so schneller. Im Build ist das sichtbar:

main-….js           | main          |  55.57 kB
…
Lazy chunk files    | Names         |  Raw size
chunk-….js          | flight-detail |   1.78 kB

Häufige Fehler

4 Fehler · zum Aufklappen klicken
'router-outlet' is not a known element

RouterOutlet fehlt im imports-Array von App.

Fix: imports: [RouterOutlet, AirportHeader]. Gleiches gilt für RouterLink in der Detailseite.

Link lädt die ganze Seite neu

Im Template steht href="/" statt routerLink="/".

Fix: routerLink verwenden – dann wechselt nur der Inhalt des router-outlet.

Detailseite meldet, dass der Input id keinen Wert hat

Der Routen-Parameter kommt nicht als Input an, weil withComponentInputBinding() fehlt.

Fix: provideRouter(routes, withComponentInputBinding()). Der Input muss genauso heißen wie der Parameter in der Route.

Nach dem Neuladen von /flight/2 kommt 404

Ein einfacher Webserver kennt nur echte Dateien. ng serve liefert für jede URL die index.html aus – ein eigener Server muss das ebenfalls tun.

Fix: Den Server so einstellen, dass unbekannte Pfade auf index.html umgeleitet werden („SPA-Fallback“).

Aufgaben

3 Aufgaben + Bonus · zum Aufklappen klicken
Aufgabe 1 Flug löschen

Ein Button auf der Detailseite löscht den Flug (DELETE /api/flights/:id) und navigiert danach mit dem Router zurück zum Board.

Aufgabe 2 Status ändern

Ein <select> auf der Detailseite ändert den Status über PATCH /api/flights/:id. Die Anzeige aktualisiert sich mit dem Flug aus der Antwort.

Aufgabe 3 Eigene 404-Seite

Lege eine Komponente NotFound an und zeige sie für path: '**' statt der Umleitung. Mit einem routerLink geht es zurück zum Board.

Bonus Filter in der URL

Speichere den Typfilter als Query-Parameter, z. B. /?type=arrival. Dann lässt sich eine gefilterte Ansicht als Link weitergeben. Tipp: Auch Query-Parameter kommen mit withComponentInputBinding() als Input an.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was entspricht im Angular Router dem <Outlet /> aus React Router?

Erklärung: An dieser Stelle setzt der Router die Komponente der aktuellen Route ein. RouterOutlet muss im imports-Array von App stehen.

Frage 2 Ein Link lädt die ganze Seite neu. Was steht wahrscheinlich im Template?

Erklärung: Mit routerLink wechselt nur der Inhalt des router-outlet, ohne Neuladen.

Frage 3 Wie navigiert man aus dem TypeScript-Code zur Detailseite eines Flugs?

Erklärung: Das entspricht useNavigate() in React Router.

Frage 4 Wie kommt der Routen-Parameter :id in die Detailseite?

Erklärung: Werte aus der URL sind immer Strings; für den Vergleich mit einer numerischen ID wandelt man sie um.

Frage 5 Was bewirkt loadComponent in einer Route?

Erklärung: Große Apps starten so schneller, weil selten genutzte Seiten nicht im ersten Download stecken.
