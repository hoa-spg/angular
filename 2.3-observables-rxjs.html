Observables & RxJS

Angular RxJS ca. 90 min Fortgeschritten

Lernziele

  • Observables als Datenströme verstehen und von Promises abgrenzen
  • Streams mit pipe und Operatoren wie switchMap, catchError, debounceTime umformen
  • Daten regelmäßig neu laden (Polling)
  • Abos mit takeUntilDestroyed automatisch beenden
  • Signals und Observables mit toObservable und toSignal verbinden

1 — Observable und Promise

In Lektion 2.2 hat getFlights() ein Observable geliefert, das genau einen Wert brachte. Observables können aber viel mehr: Sie sind Datenströme, die über die Zeit beliebig viele Werte liefern – Tastendrücke, Timer-Ticks, wiederholte Requests.

PromiseObservable
Anzahl Wertegenau einerbeliebig viele

Die Bibliothek dafür heißt RxJS; Angular verwendet sie für HttpClient, Formulare und Router.

2 — Operatoren

Mit stream.pipe(op1, op2, …) entsteht ein neuer Stream, der die Werte nacheinander durch die Operatoren schickt – wie map und filter bei Arrays, nur über die Zeit. Diese verwenden wir im FlugBoard:

OperatorWirkung
interval(30_000)erzeugt einen Stream, der alle 30 Sekunden einen Wert liefert (0, 1, 2 …)
startWith(0)liefert sofort einen ersten Wert – sonst käme der erste erst nach 30 Sekunden
switchMap(() => …)macht aus jedem Wert einen neuen Stream (hier: einen HTTP-Request) und liefert dessen Ergebnis. Kommt ein neuer Wert, bevor der alte Request fertig ist, wird der alte abgebrochen.
catchError(() => …)fängt einen Fehler ab. EMPTY ist ein Stream ohne Werte – der Fehler wird „verschluckt“, der äußere Stream läuft weiter.
debounceTime(300)lässt einen Wert erst durch, wenn 300 ms lang kein neuer kam

3 — Automatisch aktualisieren

Ein Abflugmonitor muss aktuell bleiben. Statt die Flüge einmal zu laden, bauen wir in ngOnInit einen Stream: sofort und dann alle 30 Sekunden ein Request.

src/app/app.ts (ngOnInit) typescript 
  // ngOnInit: läuft einmal, wenn die Komponente erstellt ist
  ngOnInit(): void {
    // Sofort und danach alle 30 Sekunden die Flüge laden
    interval(30_000)
      .pipe(
        startWith(0),
        switchMap(() =>
          this.api.getFlights().pipe(
            // Fehler abfangen, damit der Stream weiterläuft
            catchError(() => {
              this.error.set('Backend nicht erreichbar – läuft „deno task dev“?');
              this.loading.set(false);
              return EMPTY;
            }),
          ),
        ),
        takeUntilDestroyed(this.destroyRef),
      )
      .subscribe((flights) => {
        this.flights.set(flights);
        this.error.set('');
        this.loading.set(false);
        this.lastUpdated.set(new Date());
      });
  }
  • Das catchError sitzt innerhalb von switchMap. Stünde es außen, würde ein einziger Fehler den ganzen Stream beenden – das Polling wäre vorbei.
  • lastUpdated merkt sich den Zeitpunkt; im Template formatiert ihn die date-Pipe aus Lektion 1.4.

Aufräumen mit takeUntilDestroyed

Ein interval läuft ewig. Wird die Komponente entfernt – etwa beim Seitenwechsel in Lektion 2.4 –, liefe es im Hintergrund weiter (Memory Leak). takeUntilDestroyed(this.destroyRef) beendet das Abo automatisch, wenn die Komponente zerstört wird. DestroyRef holt sich die Komponente mit inject.

4 — Signals und Observables verbinden

Bei jedem Tastendruck filtert filteredFlights neu. Mit einem Debounce wartet die Suche, bis man kurz aufhört zu tippen. debounceTime ist ein RxJS-Operator, der Suchtext aber ein Signal – Angular kann beides ineinander umwandeln:

  • toObservable(signal) macht aus einem Signal einen Stream, der bei jeder Änderung einen Wert liefert.
  • toSignal(observable, { initialValue }) macht aus einem Stream wieder ein Signal. Bis zum ersten Wert gilt initialValue.
src/app/app.ts (Ausschnitt) typescript 
  // Suche erst anwenden, wenn 300 ms lang nicht getippt wurde
  private debouncedSearch = toSignal(toObservable(this.searchText).pipe(debounceTime(300)), {
    initialValue: '',
  });

  // computed: wird neu berechnet, sobald sich ein gelesenes Signal ändert
  filteredFlights = computed(() => {
    const q = this.debouncedSearch().trim().toLowerCase();
    return this.flights()
      .filter((f) => this.activeType() === 'all' || f.type === this.activeType())
      .filter(
        (f) =>
          !q ||
          f.flightNumber.toLowerCase().includes(q) ||
          f.airline.toLowerCase().includes(q) ||
          f.airport.toLowerCase().includes(q),
      );
  });

Das Suchfeld bleibt an searchText gebunden; gefiltert wird mit debouncedSearch.

Die vollständige Klasse und die neue Zeile in der Toolbar:

src/app/app.ts typescript 
import { DatePipe } from '@angular/common';
import { Component, DestroyRef, OnInit, computed, inject, signal } from '@angular/core';
import { takeUntilDestroyed, toObservable, toSignal } from '@angular/core/rxjs-interop';
import { FormsModule } from '@angular/forms';
import { EMPTY, catchError, debounceTime, interval, startWith, switchMap } from 'rxjs';
import { AddFlightForm } from './add-flight-form/add-flight-form';
import { AirportHeader } from './airport-header/airport-header';
import { FlightCard } from './flight-card/flight-card';
import { Flight, FlightType } from './flight';
import { FlightApi } from './flight-api';

@Component({
  imports: [DatePipe, FormsModule, AddFlightForm, AirportHeader, FlightCard],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App implements OnInit {
  private api = inject(FlightApi);
  private destroyRef = inject(DestroyRef);

  // Startwert: leere Liste – die Flüge kommen vom Backend
  flights = signal<Flight[]>([]);
  loading = signal(true);
  error = signal('');
  lastUpdated = signal<Date | null>(null);
  selectedFlight = signal<Flight | null>(null);

  // Suchtext und Typfilter werden im Template geändert
  searchText = signal('');
  activeType = signal<'all' | FlightType>('all');

  // Suche erst anwenden, wenn 300 ms lang nicht getippt wurde
  private debouncedSearch = toSignal(toObservable(this.searchText).pipe(debounceTime(300)), {
    initialValue: '',
  });

  // computed: wird neu berechnet, sobald sich ein gelesenes Signal ändert
  filteredFlights = computed(() => {
    const q = this.debouncedSearch().trim().toLowerCase();
    return this.flights()
      .filter((f) => this.activeType() === 'all' || f.type === this.activeType())
      .filter(
        (f) =>
          !q ||
          f.flightNumber.toLowerCase().includes(q) ||
          f.airline.toLowerCase().includes(q) ||
          f.airport.toLowerCase().includes(q),
      );
  });

  // ngOnInit: läuft einmal, wenn die Komponente erstellt ist
  ngOnInit(): void {
    // Sofort und danach alle 30 Sekunden die Flüge laden
    interval(30_000)
      .pipe(
        startWith(0),
        switchMap(() =>
          this.api.getFlights().pipe(
            // Fehler abfangen, damit der Stream weiterläuft
            catchError(() => {
              this.error.set('Backend nicht erreichbar – läuft „deno task dev“?');
              this.loading.set(false);
              return EMPTY;
            }),
          ),
        ),
        takeUntilDestroyed(this.destroyRef),
      )
      .subscribe((flights) => {
        this.flights.set(flights);
        this.error.set('');
        this.loading.set(false);
        this.lastUpdated.set(new Date());
      });
  }

  onFlightSelect(flight: Flight): void {
    this.selectedFlight.set(flight);
  }

  addFlight(data: Omit<Flight, 'id'>): void {
    // Das Backend vergibt die id und liefert den gespeicherten Flug zurück
    this.api.addFlight(data).subscribe((flight) => {
      this.flights.update((list) => [...list, flight]);
    });
  }
}

Häufige Fehler

Polling hört nach dem ersten Fehler auf

catchError steht nach switchMap in der äußeren pipe. Ein Fehler beendet dann den ganzen Stream.

Fix: Den Fehler am HTTP-Observable innerhalb von switchMap abfangen.

Erster Request erst nach 30 Sekunden

interval liefert seinen ersten Wert erst nach Ablauf der Zeit.

Fix: startWith(0) direkt nach interval.

toSignal() can only be used within an injection context

toSignal oder toObservable wird in einer Methode wie ngOnInit aufgerufen.

Fix: Direkt bei der Deklaration des Feldes aufrufen – wie inject.

Aufgaben

Aufgabe 1 Jetzt aktualisieren

Ein Button „↻ Aktualisieren“ soll sofort neu laden. Lege einen Subject<void> an (ein Stream, in den man mit next() selbst Werte schickt), rufe im Button refresh.next() auf und kombiniere beide Auslöser mit merge(interval(30_000), this.refresh).

Aufgabe 2 Intervall verkürzen und beobachten

Setze das Intervall testweise auf 5 Sekunden und beobachte den Netzwerk-Tab. Ändere in der Datenbank (oder per PATCH) einen Status – wann erscheint er?

Aufgabe 3 Suche im Backend

Das Backend kann mit ?search=os selbst suchen. Baue einen zweiten Stream: toObservable(this.searchText) → debounceTime → switchMap zu getFlights mit Parameter. Warum ist switchMap hier wichtig?

Bonus Ohne Signal: async-Pipe

Statt zu abonnieren kann das Template einen Stream direkt anzeigen: {{ zeit$ | async }}. Zeige damit eine Uhr an, die jede Sekunde weiterläuft (interval(1000) und map(() => new Date())).

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was unterscheidet ein Observable von einem Promise?

Mehrere Antworten sind richtig.

Erklärung: Ein Promise liefert genau einen Wert, startet sofort und lässt sich nicht abbrechen. Observables formt man mit Operatoren in pipe(…) um.

Frage 2 Was macht switchMap(() => this.api.getFlights()) im Polling-Stream?

Erklärung: switchMap „wechselt“ immer auf den neuesten inneren Stream.

Frage 3 Warum kommt der erste Request erst nach 30 Sekunden, und wie behebt man das?

Erklärung: startWith(0) liefert sofort einen ersten Wert, danach kommt alle 30 Sekunden einer.

Frage 4 Das Polling hört nach dem ersten Fehler auf. Was ist die Ursache?

Erklärung: Fängt man den Fehler innen ab (z. B. mit EMPTY), fällt nur dieser eine Request aus, das Intervall läuft weiter.

Frage 5 Wozu dient takeUntilDestroyed?

Erklärung: Ohne Aufräumen laufen Abos im Hintergrund weiter, z. B. nach einem Seitenwechsel.
